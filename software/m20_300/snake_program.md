# M20-300 Snake 核心机器程序

`snake.asm`是16-bit word-addressed ISA的真实汇编输入；本轮没有OLED输出、像素刷新、软件消抖或计时循环。CPU执行方向、运动、边界/自身碰撞、身体环、占用位图、食物探测、长度/得分及重启，解释器中没有Snake快捷指令。

## 入口与运行约定

- ROM word 0是`boot`。CPU通过间接写循环清全部256个nibble RAM，再初始化三个身体位置`(2,3),(3,3),(4,3)`，头槽2、尾槽0、方向右、长度3、食物`(10,3)`、得分0、运行状态0。
- `boot`设置event=4后到`tick_done`，不额外移动一步。正常继续执行`NOP; JMP tick`，以后每次tick自行读IN0/IN1并更新一次。
- 测试可在`tick_done`设只读断点，观察后继续；没有宿主回写下一帧。为检查边界，独立夹具允许在CPU复位时装入合法初始RAM并从`tick`入口运行，必须与正常boot测量区分。
- 本版汇编结果为368 words / 736 bytes，占4096-word ROM约8.98%。标签地址须以实际汇编结果为准；当前boot=0、tick=34、tick_done=316、occupancy_lookup=318。

## 数据布局

|nibble地址|名称|语义|
|---|---|---|
|00/01|HEAD_LO/HI|头槽索引，低/高nibble，0..63|
|02/03|TAIL_LO/HI|尾槽索引，0..63|
|04/05|LEN_LO/HI|长度，正常1..64|
|06|DIR|0右、1下、2左、3上|
|07/08|FOOD_X/Y|x0..15、y0..7|
|09/0A|SCORE_LO/HI|无符号8位，增长时加1并模256|
|0B|STATUS|0运行、1死亡、2封顶、3位图搜索不变量错误|
|0C/0D|KEYS0/KEYS1|本tick读取的输入银行；boot会清零|
|0E|EVENT|0普通/保持、1增长、2死亡、3封顶、4初始化/重启、5搜索不变量错误|
|0F/10|PROBES_LO/HI|本tick食物候选检查次数；非增长/死亡保持为0|
|11/12|NEXT_X/Y|候选新头|
|13/14|OLD_TAIL_X/Y|当前旧尾坐标|
|15|GROW|新头是否等于食物|
|17/18|ADDR_LO/HI|动态身体地址|
|19/1A|BIT_LO/HI|位图nibble地址|
|1B|MASK|1/2/4/8位掩码|
|1C|OCCUPIED|共享查询结果0/1|
|1D/1E|LOOK_X/Y|共享查询参数|
|1F/20|INDEX_LO/HI|身体地址计算参数|
|21|TEMP2|清位用反相掩码|
|40..BF|身体环|槽i的x在40+2i，y在41+2i|
|C0..DF|占用位图|`p=16*y+x`；地址C0+floor(p/4)，位1<<(p mod4)|
|F0|RETURN_ID|软件返回编号，0无效，1..4为有效调用点|

16标为保留工作单元；其余未用globals/scratch由boot清零，CPU不依赖解释器的默认零RAM。身体槽中不在活动环内的旧值允许保留，不应把它们误判为活动身体或额外占用。

## 规则

- IN0 b0上、b1下、b2左、b3右。只考虑第一个按下键；如果它与当前方向相反，拒绝而保持原方向，不继续尝试更低优先级键。
- IN1 b1（总key mask bit5）优先重启。其它IN1位目前仅记录，不承担游戏功能。死亡/封顶时仍可读取重启；无重启则不移动，event/probes归0。
- 越界即死亡，不把4-bit溢出当合法穿墙。发生死亡时头/尾索引、身体、位图、长度、食物及得分保持；方向可按本tick输入改变。
- 非增长时允许进入本tick将释放的旧尾；先清尾位，再设新头位。增长时不移尾，相同位置仍属自身碰撞。
- 索引模64；增长到64时先完成新头、位图、长度及得分，再设置封顶，不再搜索食物。若夹具提供“运行且已64节”并再次增长，则直接封顶、不覆盖身体槽。
- 食物从旧食物线性位置+1开始，按模128线性探测空位，全由CPU计算。不是随机算法，不声称分布均匀或完整游戏随机体验已完成。
- 若65个候选都被占用，显式返回status3/event5，避免损坏位图导致无界循环。合法长度≤64和一致位图不会触发该分支；这不是对任意损坏RAM的完整防护。

## 单层软件返回

共享函数`occupancy_lookup`接收LOOK_X/Y，计算BIT_LO/HI、MASK、OCCUPIED，并留下指向位图nibble的AR。结束时从普通RAM的F0读取RETURN_ID，执行SUBI/JZ链分派；不存在硬件CALL/RET、LR或宿主函数。

|返回编号|调用用途|返回标签|
|---:|---|---|
|1|检查候选新头|after_collision_lookup|
|2|定位旧尾并清占用位|after_tail_lookup|
|3|定位新头并设占用位|after_head_lookup|
|4|检查食物候选|after_food_lookup|

函数可破坏A/Z/C和AR，输出位置明确定义。函数内部不再调用其它函数。非法返回编号进入诊断HALT，不靠Python解释器分派游戏控制流。

## 本地程序烟测记录

以下为使用当前汇编器/指令解释器执行得到的计数，**不是RTL时序或157实物测量**。计数从boot/tick入口到tick_done之前，未执行断点处NOP和后续JMP；普通指令2、RAM指令5微周期，reset固定1另列。

|场景|执行指令|RAM读|RAM写|CPU模型周期（不含reset1）|
|---|---:|---:|---:|---:|
|完整CPU清RAM及boot初始化|1862|0|269|4531|
|初始三节蛇向右普通移动一次|256|82|56|926|
|合法62节密集身体、增长至63、63次食物探测、得分FF→00|4152|1021|684|13419|

密集场景可复现方法：生成16×8逐行蛇形路径（偶数行x递增、奇数行x递减），旧身体为`reversed(path[2:64])`，tail槽0、head槽61、dir左、food=(1,0)、score=255。增长后占用线性位置1..63，程序检查2..63后在64=(0,4)找到空位，PROBES=63。该记录是明确测试场景，不自动声称穷举证明了所有合法RAM状态的全局最坏周期。

另外用独立一步规则对600个确定性生成的合法蛇形身体/环索引/方向/按键/食物状态做本地烟测：活动身体、位图、索引、长度、得分、状态、事件与probe_count全部匹配。正式综合回归和ISA能力分析由根任务统一执行和保存；本文件不宣称这些局部烟测替代完整CPU验证。
