# M20-300 Pong核心机器程序

本程序只验证游戏核心状态、六键输入、动态RAM及单层软件返回。它使用`M20_300_architecture_v0_1.md`的16-bit指令字，不使用旧747方案的B/T/LR或硬件CALL/RET，也没有OLED渲染、软件消抖或真实帧计时。汇编器/解释器是独立通用工具；Python宿主不执行本程序的碰撞或分数更新。

## RAM与逻辑输入

|地址|变量|有效范围/含义|
|---|---|---|
|00|ball_x|1..14|
|01|ball_y|0..7|
|02|vx|0向右、1向左|
|03|vy|0向下、1向上|
|04/05|左右球拍顶部|0..5，各高3格|
|06/07|左分数lo/hi|两个nibble组成8位计数，模256|
|08/09|右分数lo/hi|同上|
|0A|event|bit0垂直墙反弹、bit1球拍反弹、bit2左得分、bit3右得分|
|0B/0C|keys0/keys1|CPU实际执行IN0/IN1的输入快照|
|20|CTRL|共享球拍例程的两位控制|
|F0|RETURN_ID|1返回左球拍调用点，2返回右球拍调用点|

IN0的bit0/1为左上/左下，bit2/3为右上/右下；同侧上下同时按下取消。IN1额外两个动作键本核心仅读取并保存，不定义开始/重启功能；最终物理键映射仍TBD。测试输入是稳定后的逻辑按键，不能把本原型等同于已经包含异步同步/机械去抖的游戏程序。

## 启动与持续运行

`boot`位于ROM指令字0。CPU自行将球设置为(8,4)、向右下，球拍顶部均2，分数/事件/输入快照/scratch/返回ID清零；随后进入`tick`。没有要求外部RAM上电为零。

`tick`读取六键，先更新球拍，再纵向更新球，再横向判断球拍接触/得分。`tick_done`是只读调试观察点，包含`NOP; JMP tick`，并非HALT；运行可以持续受按键影响。测试夹具可在CPU停止/复位时预置合法游戏状态并从`tick`启动以覆盖边界，这属于单元场景设置，不是执行时由Python替CPU更新游戏。

每个tick的独立状态规则为：

1. 球拍根据本侧按键加减1并夹在0..5；相反键同时按保持。
2. y=0向上反弹到1并改为向下；y=7向下反弹到6并改为向上；其余按vy移动一格。
3. x=1向左或x=14向右时，用**新y**检查相应球拍的闭区间top..top+2。命中后x保持接触内侧1/14并反向；未命中给对手加1分。
4. 得分后球复位(8,4)，vy向下，vx朝向刚失分的一侧；得分event覆盖此前墙反弹event。

共享`update_paddle`只使用CPU指令，通过AR进行真正的间接读写。同一机器例程被左右球拍各调用一次，使用RAM中的4-bit返回编号和显式JZ/JMP分派；没有把返回编号解释成隐藏的12位返回PC。非法返回编号走`bad_return_id`，该路径只HALT以便测试发现ABI损坏。

程序有意依赖两个将由ISA测试明确验证的能力：ST及LD保留C，使8位分数可用ADDI/ADCI推进；IN/AR控制保留flags但不依赖它们设置Z；所有需要按键判零的位置都先做LD/ANDI/SUBI。`EVENT+2`等价于`EVENT OR2`只因球拍接触前EVENT必为0或1，未假定通用OR立即数指令。

## 程序用量与周期口径

本轮共享汇编器已成功组装：**168个16-bit指令字，336字节有效代码，占4096-word ROM的4.1015625%**，无`.org`空洞。若生成填满4096-word的镜像，其文件大小是8192字节；填充容量不能当成程序实际使用量。

程序自测使用实际机器字和通用Machine解释器，固定种子`0x20300`生成10000个合法球/球拍/方向/分数/六键初态，与单独按游戏规则书写的数学状态更新比较，RAM00..0C一致。样本中`tick`到`tick_done`实际执行57..94条指令、180..308微周期；**这是该组样本的观测范围，不是已经证明的穷举最坏上界**。项目主回归应另行独立验证并保存逐场景统计。

脏RAM启动测试在首次`tick`之前检查初始化，执行19条指令、83微周期、15次RAM写，无RAM读；球为(8,4)、方向右下、两球拍top=2、分数/事件/输入快照/CTRL/RETURN_ID为0。RESET开销1周期另外记录，不包含在83执行周期中。

普通指令2周期、RAM指令5周期；每条实际路径均检查`cycles=2×retired + 3×(ram_reads+ram_writes)`。`tick`到`tick_done`区间不包含观察点后的NOP/JMP两条循环指令；持续循环时应额外计4周期，或直接统计两个观察点之间的实际完整轨迹。

这些周期是候选微架构约定下的解释器统计，不是RTL时序测量、OLED帧率或真实157 CPU主频证明。
