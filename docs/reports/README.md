## 后续阶段的记录方式

1. 确定用于验收的有效记录：实际 DUT 已连接、数据完整、条件明确，且用户已确认本阶段正式通过。
2. 从[模板](stage_report_template.md)创建 `{模块}_phase{阶段}_{YYYYMMDD}.md`，记录实际配置、逐项结果和证据路径。日期采用 Asia/Shanghai。
3. 用表格展示参数和结果；必要时增加时序图、检查量或性能曲线。图表须说明单位和依据；没有实测的数值应标为推导或仿真。
4. 写清本阶段成功的意义及尚未覆盖的范围，并说明诊断过程是否影响验收数据。
5. 核对报告与原始 JSONL、CSV、构建参数一致，更新本索引和主 README。后续验收另建报告，不覆盖旧结论。

`assets/`保存报告插图，Markdown 表格提供其对应的可读数值。正式报告和少量插图可纳入版本管理；原始数据仍在`results/`，交接时应同时归档报告引用的结果目录。仅取得 Markdown 而没有原始目录时，可以阅读结论和参数，但无法重新解析原始串口记录。

当前报告由工程协作流程维护；UART 采集程序负责保存数据，不会自行宣布某个阶段获得正式验收。
