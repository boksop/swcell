## 1. 不能直接继承Johnson服务事件

前馈发生器每个参考周期产生一个CPU微周期，`f_micro=f_REF`。旧116候选依赖八状态，FPGA服务等待同一参考的两个边沿；这套协议不能直接套用到现在的半周期透明窗。

CPU仍为4096×16 ROM、256×4 RAM、原ISA和2/5有效微周期。新的服务层不能替CPU运算/译码、增加IR或改变网表来让结果通过。若引入周期间停车等待，必须同时报告有效微周期数和墙钟时间；不能保持原性能结论不变。

## 2. 优先使用FPGA较快服务时基

|源/时钟关系|允许的分析|不允许的假设|
|---|---|---|
|FPGA由快系统时钟分频产生CLK_REF|按相关时钟关系安排服务并约束IO往返|内部命令边沿等同CPU叶端边沿、外部延迟为零|
|外部晶振CLK_REF同时送发生器和FPGA|先核对相关/派生服务时钟是否可建立；否则明确跨域|“外部”必然全异步，或可无延迟还原所有相位|
|独立50MHz系统服务外部参考|同步单bit事件，使用有界稳定总线采样窗口与截止时间|逐bit同步PC即原子、两级同步即零延迟、窄死区必被捕获|

现有50MHz系统周期为20ns。其作为候选快服务时基，不代表新板级时钟约束已经完成。参考若为100kHz，半周期约5µs；若为1MHz则约500ns，均需再扣死区及外部传播，不把设定值当实测。

两级同步器的数字模型可规定2～3服务周期的识别窗口，但真实亚稳态延迟不是绝对有界；硬件MTBF、同步寄存器布局及预算需单列。对相关源也需约束发生器/CPU/FPGA引脚的路径，不能以“同源”删除建立保持分析。

## 3. 建议的长期稳定服务窗口

C上升后Master关闭，链和译码延迟后Slave打开，CPU Q/PC/微状态变化；高半周期中部可形成总线稳定区。C下降后Slave关闭，延迟后Master打开，低半周期用于组合结果建立。

### ROM

在Slave更新后的PC已经稳定时，FPGA一次采样完整12位地址，启动同步BRAM读取，再把寄存的ROM输出保持到指定允许更新窗口。CPU无IR，不能在执行或访存过程中随短暂PC过渡改变指令。

保守初始契约可以要求ROM在下一Master透明前稳定；若采用Master窗口内更新，必须另证从ROM变化到所有D函数稳定的预算，并避免控制瞬态被错误采样。不要混用两种口径。

### RAM

RAM地址、A数据及CE/OE/WE由CPU现有组合逻辑提供。FPGA在其已稳定的窗口锁存完整事务，读数据通过同步BRAM返回并保持，必须在对应Master最终关闭前留足CPU组合路径建立时间。

写入不必挤在几十ns的D1：可在定义的较长稳定窗口完成一次持久化，但必须重新定义该服务事件与ISA退役、复位取消/不回滚的关系。对WE的一个连续有效区只生成一次事务；跨SAFE_HOLD保留完成身份，不能因电平未变而重复写。

这里没有选定最终持久写时刻。必须先建立最小程序和7组访存/复位证据，再冻结服务接口版本；不能沿用旧名称而悄悄改变物理提交点。

## 4. 可计算的预算

|路径|预算包含项|截止条件|
|---|---|---|
|参考→PC采样|FPGA输出/输入或外部源分配、tap最慢、Slave译码/钳位/Buffer、有效开启、Q更新、CPU→FPGA PCB、输入setup|完整PC稳定后才采|
|ROM服务→CPU|事件识别/调度、地址寄存、BRAM边沿数、FPGA输出、PCB、ROM输入稳定guard|满足已选ROM更新窗口|
|RAM读→Master采样|总线稳定/采样、BRAM延迟、FPGA IO/PCB、CPU组合传播、Master有效关闭/setup guard|实际最晚返回早于实际最早采样关闭|
|写事务|采样、单次持久化、复位边界、后续读可见性|无重复、无丢失；已提交不回滚|
|STOP|请求识别、当前完整提交、pending处理、SAFE_HOLD传播、叶端关闭|确认后状态/事务保持|

每个值必须注明datasheet、assumed、RTL推导或实测。tap16带来更长死区，但也可能推迟Q/PC并缩短高/低服务窗口；推荐tap必须联合这两个方向，不只最大化D1/D2。

PCB/IO值未知时保留待标定项或明确设计上限假设，不能填0ns并称真实裕量。不能为了通过而增加全局false_path或放宽CPU比较。

## 5. 分层验证与状态

1. 固定20颗结构/小型DFF角落建立可用窗口后，选择候选tap及频率。
2. 用最小LDI/LD/ST/OUT/HALT、PC变化及间接RAM场景核对服务与CPU提交对齐。
3. 运行复位、SAFE_HOLD、STOP/STEP中待写取消/已写保留/重复写负测，给出真实服务事件日志。
4. 三模式再运行原49指令、38游戏、57331事件、50521非法终态和原有异常专项；每个模式分别报告零延迟功能及带延迟结果。

若稳定窗口不足，先标UNSUPPORTED/NOT_VERIFIED并报告具体预算，不把FPGA接口失时当CPU失效，也不通过修改ISA或CPU网表掩盖。若所有tap的小型叶端条件已失败，应停在V2.4-B，本层和完整CPU均为NOT_VERIFIED。

## 6. 本轮A/B证据对服务层的实际约束

小型测试的名义全局D1/D2为8/16/24/32ns，均可能接近或短于几个20ns系统周期；更不能要求完整BRAM访问塞入其中。独立快慢、上/下降非对称及钳位/分配差异会进一步压缩或倒转有效边界。故服务方案继续以较长稳定高/低窗口和截止时间预算为准，不通过“捕获每个D1/D2”来构建必达协议。

在11个normal_assumed场景内，TAP16的最坏有效裕量6ns达到assumed 4ns guard；但0.5ns/级快速链敏感性下仍为−2ns且每tap都有4个跨位流水错误，不能据前一个受限集合批准B/C抽头。未给出保证最小传播，尚无实体推荐抽头，也不能先开始C/D让CPU运行成功替代叶端时序条件。

SAFE_HOLD的小型手动park/resume只证明给定时序下的叶端保持；完整50MHz同步/CDC、单步、重复WE处理和RAM复位持久化仍为NOT_VERIFIED。已有V2.3模式A、旧116候选的服务/CPU结果保留历史，不列作本前馈版本的验收证据。

下一步应先解决最小延迟条件、时序边界/修正方案并重新评审门槛；只有可用抽头和适用频率被明确批准，才进入本文件第5节的最小服务测试。原始证据与结论见[small_verification.json](ff16_resources/small_verification.json)及[M20_V24_TEST_REPORT.md](M20_V24_TEST_REPORT.md)。

## 7. C/D 最终数字服务契约（取代“待实现”状态）

FPGA 50MHz；实际 REF 两级同步后，低 age4 锁存 RAM 请求，低 age14 快照 PREVIEW；高 age0 持久写，高 age4 观察已由 Slave 更新的 CPU，高 age8 锁存 ROM 地址，高 age12 执行停车/释放。B 实际 RAM/预览偏移为下降后 160/360ns，写/观察/ROM 为上升后 80/160/240ns；C 对应 140～159/340～359ns 与 60～79/140～159/220～239ns。详见[实际事件 CSV](ffcd_resources/service_latency.csv)。

ROM/RAM 为同步两服务周期返回，剩余时间保持。CPU 没有新增 IR、等待微状态或译码；普通/RAM 指令仍 2/5 微周期。PREVIEW 是验证快照，真实 CPU 提交完全由 20 颗的 H/S 控制。写在高窗持久化一次，RESET 前后语义和旧 V23 内部 commit_ce 分开说明，不悄悄复用旧物理提交点定义。

六配置各 7 组内存/复位专项、全部 87 场景及跨模式完整 RAM 比较通过。逻辑读与重复 BRAM 采样必须区分：原 CE/OE 跨三状态，因此可多次采样同一逻辑请求；每次逻辑写只持久化一次。停钟与写边界控制另见[SAFE_HOLD](M20_V24_SAFE_HOLD_CONTROL.md)。当前数字接口可用；实际 IO/PCB/亚稳态与 STA 仍未验证。
