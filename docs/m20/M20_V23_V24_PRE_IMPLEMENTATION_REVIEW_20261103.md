## 3. Johnson候选的已确认结构问题

### 3.1 正常环正确；非法状态不会自恢复

纯状态转移`q_next={q[2:0],~q[3]}`枚举得到两个独立8状态环：

|类别|循环|
|---|---|
|正常|0000→0001→0011→0111→1111→1110→1100→1000→0000|
|非法|0010→0101→1011→0110→1101→1010→0100→1001→0010|

正常环中译码确实为3个Master、1个D1、3个Slave、1个D2；f_micro=f_ref/8。复位目标1000为安全死区，若先真实复位且按约束释放，逻辑上可以从下一个0000开始完整微周期。

非法环没有自动转回1000的路径。静态真值仍满足S⇒H，不能误称“任何非法状态都静态同时透明”。但非法环破坏3/1/3/1节拍，且0101→1011等同时改变q3/q2（01→10）：偏斜中间态可能经过00或11，引入Master或Slave毛刺。合法环单bit变化，不能笼统说正常译码一定有毛刺。若增加检测/恢复/输出保护，必须独立计数并处理恢复过渡。

### 3.2 自主发生器自身仍是未经互锁的原始单时钟DFF

ZIP `swc157_phasegen_johnson8.v:35–36`中Master和Slave的S直接接同一个clk_ref；四个DFF在62–65行共享此连接。

参考时钟上升时，Master“关闭”和Slave“打开”由不同实际MUX选择路径完成；若某Slave先打开而对应/上游Master后关闭，q_i→reset选择→下一Master可形成竞争路径。降低频率会增加建立时间，但不能自动消除同边沿的最小延迟/hold竞争。下游CPU具有完整参考周期死区，并不能修复发生器自己的DFF。

此为**尚未闭合的可实现性风险**，不是已经运行延迟仿真得到的失效结果；现有参考零延迟结构和原生FF参考均不能证明该风险消除。按用户要求，必须先选定解决方向，再做时序负测和完整回归。

### 3.3 17颗计数仅对连续运行参考成立

静态层级展开：8存储MUX+1反相+4同步复位选择+2译码+2复位钳位=17。未包含安全停钟保持、单步请求捕获/确认、CDC、非法恢复、内部时钟互锁以及Buffer。

候选端口只有clk_ref/rst，没有RUN/STEP输入。不能将参考的17颗标为本任务完整功能预算；新增控制状态属于发生器，需与543颗CPU核心分开审计。

### 3.4 任意停振不能靠同步计数器保证安全停车

若参考在1111/1110/1100停振，输出会持续H=1/S=1，Slave保持透明；仅依赖参考边沿的控制器无法再前进到1000。没有独立时间基准或外部故障/复位输入，无法区分“时钟丢失”与“合法长周期”。

需要区分：正常STOP请求（参考继续，等待安全边界停车）、外部紧急钳位（可关闭输出但可能中断CPU事务，重启需重新初始化）、无时基时不保证自动检测停振。不能以任意门控clk_ref替代停车控制。

## 4. 建议先评审的方案

### A. 把相位源与FPGA存储服务分离（建议）

CPU核心和ISA保持。先定义独立时钟/服务接口，可选择将CLK_REF接入FPGA、增加来源明确的相位/服务标记或状态反馈；FPGA负责有界延迟的同步、地址快照、BRAM响应和单次写，不能继续读取旧调度器计数器来猜外部相位。

须写出可计算的CDC最大识别时间、BRAM服务、IO往返及guard总预算，满足ROM更新在Master关闭期、RAM数据在采样关闭前稳定。两级同步加边沿检测不能假定零延迟，也不能无条件保证捕获短脉冲。同步后收到的事件不能冒充原物理边沿同刻的commit_ce；写可见窗口和先后次序必须明确定义。若窗口无法满足，先评审降频/窗口调整/握手方案，不擅自改变CPU的2/5契约。

模式A保留原服务；模式B/C共用同一外部服务适配层。请求/确认可以由FPGA承担接口控制，但不能替CPU计算或偷偷把发生器状态寄存器放到FPGA。

### B. 给Johnson自身的4个DFF增加本地互锁相位前级（候选，未验证）

可先研究纯MUX互锁关系：`H_local = CLK_REF OR S_local`、`S_local = CLK_REF AND H_local`，再由本地H/S驱动计数器Master/Slave。两条布尔关系可用MUX表达，设计意图是上升先关闭Master再打开Slave，下降先关闭Slave再打开Master。

**这不是已完成的修复方案。** 它含异步反馈，须检查初始化、数据/选择弧、最小死区与四位分支skew；由传播链产生的短间隔不等同于完整参考周期死区，更不保证任意器件负载下安全。不宣称“加两颗即可完成V2.4”。若该前级不能建立有界安全条件，再评审其他纯157握手/锁存结构，不进入盲目长回归。

先确定这一方向或用户认可的其他结构，再逐模块验证，不直接复用原raw-clock双MUX DFF为已证明实现。
