# M20 V3 时钟与同步存储契约

50MHz唯一时钟，20ns。固定服务窗口至少50系统周期；周期设置50/100/500分别给出主动1MHz/500kHz/100kHz。只有停车时采纳改速请求，系统服务和OLED始终50MHz。

`phase_count=k`表示一段20ns状态；组合使能在该段为高，于其结束的下一posedge采纳，因此不能少算一个服务边沿。

|事件|相位定义|相对周期开始的实际服务时刻（50MHz）|
|---|---|---:|
|Master透明|phase<20且active|0～400ns（严格模型）|
|同步键/复位控制保持|在phase0末采纳|20ns起稳定|
|RAM请求锁存|phase4末|100ns|
|RAM同步数据返回|请求后下一边沿|120ns，随后保持|
|PREVIEW/退役条件锁存|phase19末|400ns，保持至提交统计|
|Master关闭|phase进入20|400ns|
|持久RAM写|phase21末|440ns，仅一次pending写|
|Slave透明|phase25～39|500～800ns（严格模型）|
|F模式CPU FF提交|CE在phase25为高，末边沿采纳|520ns|
|ROM地址采样 / 同步返回|phase28末 / 下一边沿|580 / 600ns|
|Slave关闭|phase进入40|800ns|
|CPU/总线调试注册快照|phase45末|920ns|
|周期结束|phase49末，或更大周期末|最短1000ns|

F的提交落在允许的Slave窗口中，较严格模型打开晚一个系统边沿；两模式在F提交后的观察边界比较完整状态，不声称门级边沿完全重合。严格H/S只是数字调度模型；其Fabric反馈不能签核，F不依赖这些信号构建时钟。V24实体20颗前馈链没有放入FPGA时钟路径。

无IR：ROM在PC更新后采样，下一Master窗口之前返回，并在整个指令执行期间保持。RAM仅在CPU原三访存状态服务，读可重复采样；WE只在MEM_ACCESS生效，pending在440ns持久写一次。复位请求先结束当前完整微周期，再取消下一轮未提交事务；已写不回滚、CPU复位不清RAM。这是V3同步控制层契约，不能冒充V21异步外部复位的相同物理取消时刻。

配置完成时RAM初值0用于确定原型启动；游戏仍执行原boot初始化（Snake自行清全部256单元）。CPU复位执行两个reset提交，再强制一个RESET→FETCH释放微周期，即使RUN已停止也完成释放。STOP完成当前微周期；`n`单步是一个微周期，不是一条指令。

每次tick到达原 `tick_done`、FETCH_WAIT边界后停车；只读端口用258个系统边沿构建内部缓冲，再一次提交完整1024bit快照与frame_game/frame_ticks，防止撕裂快照。恢复继续执行原NOP/JMP，不跳指令。显示另取整帧输入快照。

实际ROM为4×RAMB36、RAM为1×RAMB18（当前F04及乱序变体路由报告）。不因ram_style声明便认定BRAM；以ram.rpt为证。所有内部路径按20ns检查，**没有CPU multicycle或全局false_path**；当前实现9个有效异步输入（KEY4忽略后被优化），CDC为9个CDC-3信息项，无多时钟数据总线。F02/F03旧报告的10项保留历史口径。

软件完成断点使用参数，默认原版Pong=141/Snake=316；固定乱序食物变体必须显式使用Snake=313。它只决定原程序何处暂停取快照，不改变2/5指令微周期、PC跳转或CPU执行内容。见[变体及软件配置](M20_V3_SNAKE_SHUFFLED.md)。
