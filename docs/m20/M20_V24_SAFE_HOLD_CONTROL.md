# M20 V2.4：SAFE_HOLD、复位、STOP与STEP契约

2026-11-04。20颗时钟核无状态，只实现延迟译码及两路输出钳位。控制器属于FPGA；本轮已执行小型park/resume与晚释放反例，但尚未实现完整运行控制，执行情况以[M20_V24_TEST_REPORT.md](M20_V24_TEST_REPORT.md)为准，不将未运行的STOP/STEP称为通过。

## 1. 逻辑与硬件默认

```
SAFE_HOLD=1 → MASTER_HOLD=1，SLAVE_OPEN=0
SAFE_HOLD=0 → 两路跟随前馈译码
```

两个钳位MUX具有独立数据/选择、上升/下降延迟；钳位输入的分配也可不同。SAFE_HOLD不直接初始化33位CPU状态。FPGA未配置、IO高阻或参考未起振时，实体输入必须具有明确的默认安全高电平；具体硬件默认网络和值在后续原理图阶段落实，本轮不虚构引脚或上电时序。

CLK_REF固定低最终会使Master透明，固定高最终会使Slave透明；这两种行为都不能替代SAFE_HOLD。停振不自动检测，若停在任一透明阶段仍需外部安全控制。异步紧急钳位可以终止透明过程，但不保证中断中的CPU事务已经完整执行；恢复应重新初始化。

## 2. 正常运行启动

1. FPGA服务控制就绪，SAFE_HOLD=1，CPU_RESET有效；保持链输入为已知参考并等待最大链/译码稳定时间。
2. 按已分析的参考阶段解除钳位，CPU_RESET继续有效，执行确定的完整Master/Slave初始化序列。
3. 确认所有CPU状态和ROM服务已准备；在定义的边界释放CPU_RESET，再进入正式计数。

参考和钳位之间不能假定任意顺序都安全。异步解除SAFE_HOLD时，若H_RAW已低，Master可能在半个窗口中途开放；若S_RAW已高，则Slave可能立即开放。第一种情况可能缩短建立时间，第二种可能把未知QM传至Q。初始化期间必须屏蔽比较和外部写，不把这些瞬态计作正式指令。

## 3. 正常STOP

推荐的协同原则是“完成当前有效CPU微周期及接受的存储服务，再在双方可安全关闭时保持”，不能切断原始时钟来碰运气。控制至少记录当前周期是否已产生Master采样和Slave提交、是否存在待写以及写是否已持久化。

可评审的停车窗口包括：

- 在已知有效死区钳位，但D1/D2可能短于FPGA服务分辨率，不能默认必能捕获。
- 在已充分稳定的Slave窗口内钳位：此时Master已经关、Q已获取QM，仅关闭Slave。必须留足距参考下降沿的guard，保证H钳位及时生效，不能与Master将要打开的路径竞争。

窗口选择须计入参考识别/调度、保持信号分配、两个钳位选择、Buffer及真实锁存有效边界。不能只写“C为高即可安全停车”；刚进入高半周期时Slave可能尚未打开或Q尚未稳定。

STOP的确认应在有效H=1/S=0、当前提交已观察、待写已处理后给出。停车期间不重复退役、不重复写；CLK_REF在外部晶振模式可继续运行。

## 4. 恢复与单步

恢复前链应再次稳定。若停车时已保证Q=QM，在合格Slave窗口解除钳位可能先重新开放相同旧QM；这次开放不应被控制器误计作一次新CPU提交。随后必须等待一个完整Master采样，再识别对应Slave提交。若此前属于紧急/错误停车、状态一致性未知，则走复位启动，不假定可无损恢复。

单步的定义为**一个完整CPU微周期**，不是一次参考信号电平变化，也不是每个Slave上升沿都算一次。普通指令仍需2微步，访存指令仍需5微步；FPGA不得增加CPU内部状态来掩盖服务窗口问题。

单步控制应完成：请求锁存→相位合格释放→完整M/D1/S/D2观察→事务收尾→SAFE_HOLD确认→单步ack。异步请求使用同步或toggle/ack，不直接作为时钟组合门。来自连续外部晶振时，不能用请求宽度等于一个参考周期来替代完整性检查。

## 5. 存储器事务

CPU暂停后，WE或其他总线信号可能仍保持在当前微状态的电平。FPGA需要对单次写建立事务身份/完成记录，在已完成写但WE尚未撤销时恢复，不能再次把同一高电平解释成新写。

- CPU_RESET取消尚未提交写；已持久化RAM不回滚，CPU复位不清RAM。
- 正常STOP必须明确是先排空pending写，还是保存为未提交后在恢复时完成一次；不能因STOP清除历史而重复写。
- 停止期间允许在双方关闭状态为稳定PC准备ROM，但不产生CPU退役或新的写事务。
- 服务协议的真实写持久点必须有独立版本和日志；不能将前馈方案的持久点冒称与V2.3内部M-close CE完全同刻。

## 6. 小型测试先行

|测试|必需观察|
|---|---|
|各参考阶段断言SAFE_HOLD|两钳位传播先后、有效透明区及可能的中途截断|
|各参考阶段解除SAFE_HOLD|缩短窗口、旧QM重开、首周期完整性|
|SAFE_HOLD与CLK_REF边沿竞争|独立最慢/最快路径，不用同值参数隐藏竞争|
|停车后继续外部参考|H/S保持安全、CPU状态不变、无重复写|
|单步/连续切换|每次恰一完整微周期，不重复提交|
|参考停振/恢复|不能自动保证停车；外部钳位与重新初始化行为|

当前小型SAFE_HOLD结果必须与完整控制器分开标注：

|执行项|实际结果|结论范围|
|---|---|---|
|safe_hold_normal，四tap|全局有效重叠0、Q保持、恢复不重复改变Q|CONDITIONAL，小型手动参考时序|
|safe_hold_late_release，四tap|各缺失1个Master窗口且各有1个数据错误|FAILED，控制时序反例有效|
|50MHz FPGA STOP/STEP/RAM控制器|未实现/未运行|NOT_VERIFIED|
|实体默认安全电平与器件/PCB交接|未测量|NOT_VERIFIED|

正常场景(mode3)先在C/Cd稳定高、Slave仍透明且Q已稳定的窗口内再等待100ns，断言SAFE_HOLD，等待100ns确认发生器和全部有效叶端均关闭；保持期间改变参考及数据，检查Q不变；在C/Cd稳定高时释放，等待100ns确认没有虚假Q更新。**park/resume期间全局me/se监视继续启用**，没有通过关闭重叠检查来通过。随后开始新的完整Master阶段。不是先等待Slave自然关闭后才断言SAFE_HOLD。

该测试使用手动控制且拉长的参考高窗口，不是已经实现的50MHz控制器，也没有覆盖连续外部晶振任意请求相位或RAM事务STEP。不能将其扩大为全部STOP/STEP验收。

晚释放反例(mode4)在下一C上升前仅1ns解除SAFE_HOLD，Master保持选择的释放路径为12ns；首个Master透明窗没有形成，随后Slave获取旧QM。四tap均记录missing_windows=1、data_errors=1。虽然其周期性D1/D2仍可为正，控制契约仍FAILED，说明仅检查周期边沿裕量不足以证明启动正确。

实际结果见[56项CSV](ff16_resources/timing_results.csv)和small_r4各tap配置/trace/错误记录。所有assumed条件下的通过仍不替代实体默认电平、建立保持、探头负载和时钟分发测量。由于快速链敏感性四tap失败，当前停止在V2.4-B，不继续实现控制器和CPU联合回归。
