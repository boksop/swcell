# M20 V2.4：固定16级链、抽头装配及负载

2026-11-04。固定16级/20颗结构审计已执行，物理时序仍NOT_VERIFIED；实际结构审计和测试证据见[M20_V24_MUX_AUDIT.md](M20_V24_MUX_AUDIT.md)、[M20_V24_TEST_REPORT.md](M20_V24_TEST_REPORT.md)。未取得的电气量一律标待测。

## 1. 固定网络和静态连接

```
CLK_REF → MUX01 → … → MUX04 → … → MUX08 → … → MUX12 → … → MUX16
                           TAP4          TAP8          TAP12          TAP16
```

每级采用同一非反相连接S=0、I0=前级输出、I1=0。四个抽头各自通过一处0Ω选择位连接Cd；0Ω不是157，不增加逻辑MUX，也不是软件运行时选择。

|TAP_STAGES|R_TAP4|R_TAP8|R_TAP12|R_TAP16|实际经过的级数|物理链数量|总MUX|
|---:|---|---|---|---|---:|---:|---:|
|4|装配|DNP|DNP|DNP|4|16|20|
|8|DNP|装配|DNP|DNP|8|16|20|
|12|DNP|DNP|装配|DNP|12|16|20|
|16|DNP|DNP|DNP|装配|16|16|20|

审计导出的`mux_connections.csv`、`tap_assembly.csv`、`tap_loads.csv`、`signal_probes.csv`应和结构SV绑定SHA，最终存放位置由本轮证据索引指定。

每次只能有一个连接到Cd，零个意味着Cd无有效驱动，多个会短接不同延迟节点的推挽输出。参数必须仅允许4/8/12/16；仿真中非法配置应拒绝，不能静默替代默认抽头。切换是断电装配变更。

即使选择TAP4，MUX05～MUX16仍存在、工作并负载前级；不能把TAP4版本审计成8颗或让综合裁剪后的网表代表物理BOM。

## 2. 每个抽头的负载不能一概相同

|节点情况|直接逻辑输入负载|还要计入|
|---|---|---|
|选中的TAP4/8/12|下一级MUX的I0＋OR/AND两个数据输入，共3个输入端|tap支线、Cd走线、0Ω焊盘、测试焊盘、探头、封装寄生|
|未选中的TAP4/8/12|下一级MUX的I0，共1个输入端|未装电阻的本节点支线/焊盘及探头|
|选中的TAP16|OR/AND两个数据输入，共2个输入端|Cd走线、0Ω与测试焊盘、探头|
|未选中的TAP16|没有后续逻辑级|末端支线/焊盘/探头，不能简单称0pF|
|普通中间级|下一级I0|级间走线、封装寄生|

未装0Ω的另一侧Cd焊盘和走线不应当被当作理想连接的电容全部直接挂到tap，但断口、邻近铜和浮空残桩仍可能产生寄生耦合；具体分配由后续几何/测量确定。保留测试点不意味着探头一直连接，探头负载应单独作为场景。

原厂输入电容典型值不是全部器件/电压/温度下的保证最大值。不能直接用“输入端数×typ电容”声称已完成板级负载签核，也不能用15/50pF测试表的典型传播时间直接乘级数推算真实链延迟。

## 3. 上升和下降分别建模

每级至少记录：上升/下降数据弧、输入与输出负载假设、附加走线/焊盘延迟。后续未选中链对所选节点的负载不能通过参数选择而消失。

`Cd`相对CLK_REF的τrise/τfall，应在同一参考点量取。抽头级数不等于精确ns；选择更长抽头通常提供更大时延，但因负载和边沿差异，仍以模型或实测结果为准，不能跳过全部四点扫描。

## 4. 测试信号定义

|逻辑测试信号|目的|边界|
|---|---|---|
|CLK_REF|发生器输入参考点|注明源/占空比/抖动和探头负载|
|TAP4、TAP8、TAP12、TAP16|链延迟与级联完整性|观测未选抽头也会加负载|
|Cd|实际装配后的选定参考|与参数/0Ω装配表绑定|
|H_RAW、S_RAW|钳位前译码|区分译码和SAFE_HOLD影响|
|MASTER_HOLD、SLAVE_OPEN|发生器最终输出|尚未经过完整Buffer树|
|Master/Slave各分支及代表叶端|全局有效交接预算|不能只选同一bit或同一分支|
|SAFE_HOLD、CPU_RESET|启动/停车与复位关系|输出钳位不等于CPU状态初始化|

这是逻辑接口/观测点定义，不指定FPGA封装引脚，不绘制PCB，不确定电阻值或测试点封装。

## 5. 抽头选择规则

先对全部抽头运行相同独立快慢/负载/偏斜角落；剔除D1或D2不满足guard、透明窗不足或出现数据穿透的配置。仅在明确的假设集内推荐裕量较大的抽头，同时列出缩短/加长的代价。

若所有抽头失败，报告当前假设与最小反例，停止进入完整CPU。未有保证的最小传播参数时，“在假设集通过”只能为CONDITIONAL，不能给出实物保证抽头或宣称TAP16天然最安全。

## 6. 实际四抽头比较（small_r4）

以下均为33×33最坏有效叶端差，单位ns；并非链的物理标定。正数仍需满足assumed guard=4ns。

|场景|TAP4 D1/D2|TAP8 D1/D2|TAP12 D1/D2|TAP16 D1/D2|
|---|---:|---:|---:|---:|
|nominal：每级上/下降2ns|8 / 8|16 / 16|24 / 24|32 / 32|
|independent_cross|−2 / −2|6 / 6|14 / 14|22 / 22|
|edge_asymmetric：链上升2ns、下降1ns|−2 / −6|6 / −2|14 / 2|22 / 6|
|fast_chain_sensitivity：每级0.5ns|−7 / −7|−6 / −6|−4 / −4|−2 / −2|

TAP12的edge_asymmetric虽D2为正，2ns仍小于4ns guard，因此不是通过。只考虑11个normal_assumed场景，TAP16最坏6ns，作为这一**受限假设集**的数字候选有余量；但快速链敏感性四点均失败，现阶段`recommended_physical_tap=null`，不能将TAP16当实物推荐值。

加载场景保存每级独立dr/df和额外探头/支线假设，并保留后续实体级；实际配置JSON同时保存六分支base和各leaf的skew分解，仿真使用相加后的叶端路径。不是五款Buffer的实测模型。56项结果在[CSV](ff16_resources/timing_results.csv)，本轮停止在A/B，不用CPU运行成功掩盖坏角落。
