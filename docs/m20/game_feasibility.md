# Pong与Snake的软件可行性和周期预算

**全部数值为条件性规划，不是程序执行或芯片性能实测。** 本次未写汇编器/机器程序。P3–P5必须把下列宏展开为真实ISA路径，得到实际ROM大小、动态指令/访存数和周期；超出预算就重算，不以FPGA加速隐藏差距。

## 1. 公共假设与显示成本

条件性屏幕例子：128×64、页高8、每逻辑单元8×8像素，对应16×8场地；CPU可直接写8个数据字节完成一个实心单元，定位命令暂按3字节。实际屏幕TBD，若寻址命令不同或不支持局部写，这些估算必须重做。

`B_display = dirty_cells × (8 + B_cmd)`，例取B_cmd=3。无整帧缓冲；CPU根据对象重叠重新生成脏单元内容，OLED模型不替它补图。

软件SPI叶例程预算：MSB检查/保存/条件分支，四条加载/OUT形成低高边沿，恢复/移位等约11–12条/bit；8bit约88–96条，加两nibble取数、地址、CS/DC、调用及返回等，给**每字节最多160条动态指令的设计配额**。按本ISA零附加等待最大单指令26周期，`160×26=4160`，取`C_byte_budget=4200`周期。要求每字节RAM访问≤12、GPIO OUT≤20。

这不是已经证明的代码路径上界：P3必须统计实际控制流，并逐项满足160/12/20配额；若不满足，先优化软件/重算帧率。不能直接拿SPI位数除CPU主频当有效吞吐。

4位MSB-first输出可使用`ADDI 8`取得原bit3进位，MOVB保存，JC选择MOSI路径；恢复数据后`MOVB A; ADD B`左移。加8后再左移丢掉进位，低位顺序仍可恢复。参数高/低nibble在RAM，B是例程临时；程序不得把被例程破坏的A/B/AR当跨调用保存值。P3须用00/FF/A5/5A及256字节穷举验证位序。

## 2. Pong主循环

```text
CPU复位 → 软件初始化RAM/屏幕/球拍/球
循环：
    读六键并完成软件消抖
    从按键更新两球拍（或冻结单玩家+简单CPU软件对手方案）
    算候选球坐标，检查上下墙、球拍、得分边界
    计算反弹、回合复位和分数
    从旧/新对象计算脏单元；重新判断每单元内容
    主循环组织页/列命令与像素字节，CALL叶SPI发射
    用软件循环补齐目标tick；继续轮询，而非播放预设帧
```

位置x用4位，y用3位有效；速度方向位及进位/借位组合处理越界，不能依赖4位回绕后才发现负坐标。球拍初始逻辑高度取2格，移动需清除尾格/绘制头格。墙壁/球拍重叠由CPU决定，不外包显示模型。

|每tick逻辑|动态指令配额|说明|
|---|---:|---|
|输入/消抖|80|六键两银行、软件状态|
|球拍更新|180|两球拍限位/按键|
|球运动/碰撞/回合|260|不借助FPGA碰撞单元|
|脏单元/像素选择|200|重叠重画，不是只擦旧图|
|计时/分数/循环|80|CALL外的管理|
|合计|800|RAM读≤120、写≤80的规划配额；访存周期已在指令CPI内|

两球拍各最多一个尾/头新旧格，共4格；球旧/新2格，稳态最多6格，即66字节。得分显示额外最多2格，突发8格即88字节。若实际球拍大小/像素形状使更多格变化，配额随之调整。

- 稳态周期：`800×26 + 66×4200 = 298000`。
- 含得分突发：`800×26 + 88×4200 = 390400`。
- 突发动态指令预算`800+88×160=14880`；ROM读取≤29760次（每指令最多2字节）；RAM访问≤`200+88×12=1256`次。这里是保守计算配额，不是已有trace计数。

## 3. Snake数据结构与正确性

建议最大64节，场地16×8；方向4种；不是商业游戏兼容要求。使用同一个完整CPU配置，无新增硬件数组/碰撞模块。

|数据|RAM安排/形式|
|---|---|
|globals|00..3F，含head/tail索引各2nibble、长度2、方向/键、头坐标、食物、score、随机状态、参数和指针临时|
|身体环形表|40..BF；槽i的x在40+2i，y在41+2i，i=0..63|
|占用位图|C0..DF；128bit，用于快速检查/标记场地单元|
|scratch|E0..FF，32nibble用于地址/软件临时和测试签名|

线性位置`p=16*y+x`，p∈[0,127]。位图nibble地址`C0 + floor(p/4)`、掩码`1 << (p mod 4)`；全部由CPU移位、掩码、加法、条件选择计算。掩码只需1/2/4/8，可用分支+LDI生成，不需要硬件变量移位器或隐藏ROM查表。

环形槽地址`40+2*i`通过多nibble算术生成并装AR。需要读写相邻y时用INCAR；AR实际动态装载示例见isa_proposal。占用位图32nibble加身体128、globals64、scratch32恰好256nibble，不溢出。不得把体长64的索引当7位存储后忘记mask到0..63。

```text
读取并消抖方向；拒绝立即反向
计算next_head；先判x/y边界（不把模回绕当合法穿墙）
grow = (next_head == food)
读当前tail坐标
如果next_head已占用且不是“非增长时恰好进入旧tail”：游戏结束
若不增长：清tail位图，推进tail索引
推进head索引，写新坐标，设置head位图
若增长：更新长度/分数，生成新的未占用食物
由CPU画head/tail/food/score脏格；继续循环
```

“先清旧tail再设新head”避免合法进入旧tail时把新头的占用位清掉。增长时不移tail，相同入口仍应判撞；长度达到64时进入胜利/封顶状态，不覆盖未释放槽。自撞/边界失败后由按键触发CPU重新初始化，屏幕只是输出。

## 4. 食物生成与最坏路径

随机完全在软件。可选8位非零Galois LFSR（例如右移、多项式/反馈mask作为待P3验证的常数），seed来自固定种子混入软件按键轮询计数；不复用FPGA PRBS模块为游戏生成食物。本阶段不把未验证LFSR周期/均匀性写成结论。

从候选p开始，若占用则线性加1模128探测下一单元。占用节数≤64且128格都可作为食物位置，所以**最多65个不同候选就能找到空格**；不会做无界随机拒绝。若将来加入不可用障碍格，必须重新证明这个界。

每次位图地址/掩码生成、RAM检查与候选推进给70条指令配额；需在P3展开验证。比仅扫描身体表的O(L)检查更适合这个低速CPU。若不用位图，最坏每候选再扫64槽，必须重算，不能沿用以下性能数字。

|Snake路径|游戏逻辑指令配额|脏格/显示字节|零附加等待周期预算|
|---|---:|---|---:|
|普通移动|600|头/尾2格，22B|600×26+22×4200=108000|
|增长+最坏食物搜索+分数|600+65×70=5150|头/尾/新食物/最多2分数格，共5格55B|5150×26+55×4200=364900|

最坏路径动态指令≤`5150+55×160=13950`，ROM读≤27900次；给固定逻辑160次RAM访问、每候选20次、每SPI字节12次的配额，RAM总访问≤`160+65×20+55×12=2120`。这些配额是未来实现验收目标，不是已经写出并跑过的程序统计。

## 5. 主频、CPI和体验

下表取**CPU微周期频率**，不是50MHz FPGA输入，也不是SPI频率。基础CPI按上面的逐指令上界计入；没有再除一个任意平均CPI。任何额外等待/软件路径超限都会降低结果。

|CPU配置MHz|Pong突发上限tick/s（390400周期）|Snake最坏上限tick/s（364900周期）|
|---:|---:|---:|
|0.1|0.256|0.274|
|0.5|1.281|1.370|
|1|2.561|2.740|
|2|5.123|5.481|
|5|12.807|13.702|

因此1MHz下不能仅凭这些配额承诺5Hz最坏游戏更新。2MHz约有5Hz级的**条件可行性**，余量很小；是否真实157能达到该频率完全未证明。FPGA原型可先验证5Hz交互，再根据trace优化；P8需实测CPU物理临界路径，而不是套用M11的100MHz。

非零等待时：`C_total = C_base + N_ROM*W_R + N_RAM_read*W_D + N_RAM_write*W_W`。上面N_RAM合计可用于保守乘max(W_D,W_W)，不能把RAM事务既算进CPI又额外加完整3拍。要用trace分开读/写得到准确结果。

## 6. ROM容量、节省办法和验收门槛

规划静态代码规模：Pong约1.5–3.0KiB、Snake约2.3–3.8KiB（每游戏独立镜像）；来源是SPI叶例程约160条以内、初始化、主循环、地址/位图宏和分支扩展的初步分配，**没有汇编输出支持**。P3以实际二进制≤3840字节验证；不满足则重审PC/编码/宏，不能只换更大物理NOR却仍用12位地址。

优化优先级：减少脏格/分数刷新频率，缩小逻辑场地或对象，复用叶例程，收紧地址/位图宏，适当降低tick，评估少量有明确资源收益的ISA改动。仅在软件trace证明瓶颈后评估50–90颗的最小SPI外设；禁止默认加入FPGA绘图/碰撞/蛇身加速器。

验收必须实际运行机器程序、可持续按键改变状态、轨迹与独立游戏模型一致；静态预设动画、宿主算下一帧、直接向OLED模型写预期图均不通过。
