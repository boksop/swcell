# M20-300：545颗候选与603颗V2的结构对比评审

日期：2026-11-02（Asia/Shanghai）。这是候选分析与隔离验证记录，不是正式采用或阶段验收。未覆盖V1/V2、冻结ISA、游戏、既有测试期望或历史数据；未执行Git暂存/提交/推送。

## 1. 结论

候选的 **479个显式组合MUX＋33bit×2存储折算＝545颗** 可以从实际Verilog和连接JSON独立核实，计数边界与V2的603颗基本一致，没有把译码/ALU转移到FPGA外围。其译码和AR网络优于当前V2，原包最大MUX拓扑深度30，V2为50。

但原包不完全等价：**非法指令在EXEC被识别后进入HALT(6)，而不是TRAP(7)**。原包Python测试通过、Pong/Snake测试通过，均不能覆盖这个缺陷。本次使用原样候选RTL的最小XSIM测试，以及接入既有V1锁步的指令/内存测试，分别复现失败。

在build隔离副本中，仅删除状态低位方程的一项多余条件，得到 **477＋66＝543颗**，最大拓扑深度29；实际通过既有49指令＋38游戏、57331事件的V1/候选/Python三方比较及7组memory/reset测试。该版本可作为后续优化候选，但本轮没有并入正式RTL，也没有改变603颗基线的历史结论。

## 4. 节省来自哪里

候选分组与V2不同。下表将候选storage组里的3个状态复位MUX归入控制；其余A/Z/C/GPO保持复位与输入/结果/标志逻辑合并比较。共享实例仍按其首次归属一次，表内差额不等同于逐门一一替换的因果分解。

|组合逻辑归属|V2|原候选|修正实验|修正实验−V2|
|---|---:|---:|---:|---:|
|译码|169|132|132|-37|
|AR更新|79|51|51|-28|
|PC更新|74|73|73|-1|
|微控制，含state复位|47|52|50|+3|
|RAM地址/控制|17|17|17|0|
|输入、ALU、结果/标志及A/Z/C/GPO更新|151|154|154|+3|
|**组合合计**|**537**|**479**|**477**|**−60**|

**译码：集中合法性判断，内部按类别控制。** V2先构造带保留位校验的各操作命中，再组合出legal和后续控制。候选将严格legal检查与内部操作分类分开：全局legal门控提交和访存，内部用major/sub的局部位直接选择。二者可以具有同样非法副作用保护，但候选少了重复校验/选择项。候选还用分层相等比较及AND/OR交换输入规范化，增加公共子表达式共享机会。不能把legal检查本身取消或将非法编码当don't-care。

**AR：按更新动作和nibble设计选择。** V2对ARL/ARH/MOVARL/MOVARH/INCAR逐项做8位选择，然后加寄存器写使能/保持。候选先以指令bit9选择立即数或A，共享4位来源；按低/高nibble分别使能加载，递增与保持直接进入每位更新路径。避免了部分重复“选回自己/再保持”的网络，因此AR少28颗。该方法不改变AR宽度、寻址或周期。

**数据通路并非全部更省。** 候选把AR/按键来源选择移到结果侧，并按指令原始位分层选择逻辑/移位结果；V2采用通用ALU构造及输入侧选择。合并同类后候选这一大组反而多3颗。因此不能用候选“alu55”直接对比V2完整“ALU107”，宣称ALU减半：两者归属边界不同。

**更浅的译码/合法性路径。** 候选按指令家族分层组织legal；V2较长的命中项OR链参与控制路径。相同单位延迟拓扑分析为50→30（修正后29），说明逻辑级数有优势。它不是真实关键路径的ns值，未证明所有路径可敏化，也不能推导Fmax比例。最大负载相同不代表每个节点的负载分布相同。

## 5. 原包功能缺陷及修正实验

原`tools/build.py`中状态低位的一项为：

```python
N.AND(S_exec, N.N(ram_exec), N.N(halt_instr), N.N(trap))
```

在EXEC执行FFFF时：`trap=1`，`ram_exec=0`，`halt_instr=0`。这项被最后的`!trap`清零；低位OR中又没有加入当前`trap`。状态高两位却均包含`trap`，最终产生`110`，进入HALT。注释写“illegal=111”与实际网络不符。

原样RTL的最小XSIM输出：

```text
ILLEGAL_BEFORE state=2 trap_event=1 retire_valid=0
ILLEGAL_AFTER state=6 expected_TRAP=7
Fatal: ILLEGAL_TRANSITION_FAIL got=6 expected_TRAP=7
```

这不是端口适配引入的差异：该最小测试直接编译ZIP中的原样`m20_300_mux.v`，没有使用适配器。

隔离修正为：

```python
N.AND(S_exec, N.N(ram_exec), N.N(halt_instr))
```

非法EXEC便会令低位为1，同时保持HALT、合法普通和RAM路径的原行为。相较原包删掉两颗live MUX，得到543。另评估“在低位OR末端显式加trap”的直接修复为546、深度31；该546副本仅完成结构计数，没有跑完整HDL回归，不作为已验证替代版。

候选原`test_isa.py`虽检查全部65536编码的legal，却在非法定向测试中只检查`trap_event`、`retire_valid`和PC，没有断言`u_next=TRAP`。游戏程序没有执行非法编码，因此也掩盖了缺陷。它说明“合法编码统计正确/游戏可运行”和“异常状态契约正确”需要分别验证。

## 7. 优劣与建议

|方面|候选方案|现有603方案|
|---|---|---|
|面积|译码/AR明显更少；修正后543|多60颗；是已审计基线，不是最小实现|
|拓扑深度|原30，修正29，明显较浅|50；控制译码OR链值得改进|
|功能正确性|原包有非法转态缺陷；修正实验通过既有完整指定回归|已通过原指定回归，异常/复位行为已有证据|
|结构复用|单个紧凑生成脚本易做局部优化，但单元边界和公共构造测试较少|通用MUX构造/ALU/译码、独立单元穷举和CPU回归分开|
|资源审计|包内audit主要数实例并硬编码33bit，未验证SV/JSON每pin或功能锥；本轮已补独立审计|已有独立审计、负向测试、来源/共享记录及可再生CSV|
|接口整合|CPU存储接口可对应；调试/退役端口与原工程不同，需要适配|直接匹配现有工具链与退役契约|
|物理可信度|真实反馈DFF、缓冲、STA均未完成|同样未完成；不能认为603版已有物理优势|

推荐保留603版作为冻结对照，将候选的局部译码和AR更新方式作为下一版优化基础。若采用候选，应带上非法转态修正，增加覆盖全部非法编码终态的专门测试，接入原有独立审计和完整回归，再形成正式候选版本。不要直接以原ZIP替换现有RTL。

本次已经表明：**603不是同ISA/同周期条件下的最小数量；面积约543颗的结构具有真实回归证据。** 但这仍不是全状态形式等价证明，也没有达到300颗。543距离300还差243颗，不对后续优化收益预作承诺。
