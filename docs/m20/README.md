## 建议摘要

推荐优先评审**4位累加器、多周期、硬布线控制、12位PC、8位RAM地址、8位指令、单层CALL/RET**方案。程序ROM与数据RAM分离；8位物理数据接口中RAM先仅使用低4位，避免打包读改写。OLED先由CPU软件bit-bang，六键同步后轮询、软件消抖。Pong和Snake全部状态更新/碰撞/绘图决策由机器程序完成。

**用户已明确RAM/ROM不使用157构造**：方案1由FPGA提供；方案2使用外部并口芯片，例如IS61WV5128BLL-10TLI-TR与MX29LV320ETTI-70G。两方案存储容量均计0颗157，只计CPU侧寄存器及接口逻辑。原627–747估算已经不包含存储阵列，因此这个澄清不会自动从747扣除一块“RAM成本”。[747逐项明细](mux_budget.md)与[机器可读CSV](mux_budget_747.csv)已补齐。

**300颗目标与本提案不相容。** 显式MUX树及状态预算为：最小配置约555–651颗，Pong/完整Snake配置约627–747颗；加20%工程余量后，完整配置建议预算至900颗。控制器尚未逐门审计，这不是已证明的上界，也不是器件采购定案。应先决定是否接受该预算，或另立以300颗为硬上限的串行架构研究。

|问题|提案回答|
|---|---|
|为什么先4位|相对8位候选约省116–156颗的规划量级；可复用ALU做PC/地址运算，但执行更慢，须用真实软件验证|
|寄存器|PC12、AR8、A4、B4、T4、IR8、LR12、Z/C/K共3位、微状态6位、等待计数2位、GPIO5位；另键同步12位、复位同步2位|
|存储器|4KiB逻辑程序ROM；256个4位RAM单元；游戏各自独立程序镜像，暂不承诺一个镜像同时容纳两游戏|
|游戏可编程性|有完整条件分支、间接RAM读写、动态AR、借位/进位及单层调用；Snake用环形身体表与32-nibble占用位图|
|性能是否足够|条件性预算：零额外等待时，Pong突发帧≤390400周期，Snake含食物搜索最坏tick≤364900周期；约2MHz才有5Hz级规划余量，真实157频率未知|
|FPGA与实物一致性|同一寄存器/微状态/ISA/总线时序；FPGA仅把状态单元绑定原生FF，真实映射恢复MUX反馈DFF|
