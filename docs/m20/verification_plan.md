# M20分层验证路线与阶段验收

**本次仅规划。P0–P8均未取得正式通过。** 文档链接/加总检查不算CPU仿真、结构审计或性能验证。

## 1. 参考与检查体系

1. 独立ISA模型：直接按本ISA数学语义执行，不调用RTL ALU/ITE函数或微状态；模型输入是机器码、初始RAM及外部按键事件。对比每个retire事件的PC/A/B/AR/LR/Z/C、RAM写和IO写。
2. 周期协议检查器：独立检测取指、写脉冲、地址/数据保持、等待、初始化、CE/暂停及单次退役；不能只对最终签名。
3. 游戏参考：以逻辑位置/规则检查球/蛇/食物/分数，输入来自相同按键场景；SPI模型只看CPU输出，按最终屏协议重建画面。参考只能比较，不回写DUT纠错。
4. 结构等价：ITE组合真值表/形式等价；原生FF状态绑定与真实MUX反馈模型在合法稳定采样点比较架构行为。物理传播/亚稳态另验，不把数字仿真当电气证明。

调试用取指PC、日志、UART、轨迹BRAM在AUX层；不进入CPU算法。T/K/IR等内部暂态不与ISA模型强行逐拍等同，可用独立微操作不变量约束；不能因它们看起来正确省掉架构级比较。

## 3. 覆盖与故障注入

|检查对象|必须覆盖|
|---|---|
|ALU|A/B各16值，Cin两值；ADD/ADC/SUB/SBC/CMP逐组合512情况/类；逻辑/SHR全值；零、溢出、无借位解释|
|flags|取指/地址更新不改变ZC；LD/LDI/IN和逻辑保留C；CMP不写A；B跨取指不丢失|
|编码/分支|全部256首字节、4类两字节目标地址；Z/C两个方向；目标各高nibble和低字节边界；PC=FFF跨000|
|调用|返回地址+2、LR复位0、RET、目标高段不被T覆盖、单层调用图；嵌套覆盖行为不能误当硬件支持栈|
|RAM|地址00/FF、每位置读写、邻接不变、读不写、WE加等待只形成一次写、SRAM/X传播与超时序模型|
|数组/位图|AR双nibble装载、进位/借位、槽63到0、身体表不越BF、位图掩码4种、清尾/设头次序|
|复位|所有微阶段；在途写仅允许当前地址旧/新不确定，禁止其它地址写；程序启动自行初始化RAM|
|按键|六路/两银行/极性、抖动/同时按/相反方向；有向用例在采样前稳定；异步压力不以瞬间raw与IN同拍强比较|
|显示|全部256字节序列、CS/DC/RESET、位序/边沿、局部窗口、重叠擦画；错误字节不得由OLED模型修正|
|负向验证|错误carry、取指一拍错位、PC+1/+2混淆、破坏B、错误lane/WE、跳过等待、丢trace、SPI位序错误必须被相应检查器检出|

原始RAM随机/X上电，CPU必须明确初始化所需状态；不能让TB默认清零掩盖软件缺陷。单元模型/指令模型/游戏模型分开，避免用同一错误状态生成实际与期望。

## 4. 时序与CDC边界

P6检查的是FPGA采样后控制/数据/计数路径；CPU step慢不自动免除50MHz STA。无必要全局false_path，所有时钟/CDC例外需能对应实际结构。多bit调试只在冻结快照后握手或用FIFO，不逐位同步递增PC/计数。

P8检查真实MUX反馈的主从交接、组合毛刺/深度、时钟扇出/偏斜、ROM/SRAM访问、方向切换、建立保持及负载。M11的一颗DFF/固定相位窗口不能外推整机。外部FPGA观察总线也需单独定义稳定采样/捕获相位，不能直接把M11的Q12/QM4当M20采样配置。

任何P6内部STA失败的配置报告FPGA_TIMING_FAILURE，不能写DUT失效；外部观测口无稳定窗口时记录CAPTURE_INCONCLUSIVE。真实CPU错误须排除观察器/参考/工具时序，并保存第一次架构差异及总数。

## 5. 指标和文件

建议保存：program.bin及带地址反汇编、ISA/微架构/台账版本、memory/IO配置、retire trace或分段hash、RAM/IO操作计数、首次差异、结果JSONL/CSV、工具报告和镜像SHA。分母用retired_instructions/game_ticks/memory_transactions，不把多位CPU差异冒称PRBS BER。

游戏每tick记录：有效CPU微周期、执行指令、ROM/RAM读写、OUT字节/脏格、输入到状态响应、trace丢失、游戏规则差异。零差异只说明该程序/输入/条件下未观察到差异，不是全程序数学证明。

未来数据建议`results/M20/<时间>/`，每个阶段先保存机器可读证据；用户正式确认后按项目模板写中文报告。当前没有这些M20数据，不生成示例“PASS”假装实测。

## 6. 门槛失败的处理

ISA不能表达数组/游戏→回P0修ISA；结构预算超限→回P0/P1，不删必要状态；ROM超3840或SPI路径超160指令/byte→优化/重算；无稳定CPU主频→降体验目标/硬件重新评审。FPGA加速器、隐藏寄存器、改参考滞后一拍都不是默认补救。

本次文档检查只核对规划中的算术/编码数量/63微状态及引用，不代替任何一行未来硬件验收。
