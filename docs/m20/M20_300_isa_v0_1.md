# M20-300：16-bit ISA与软件工具约定 v0.1

日期：2026-10-28（Asia/Shanghai）。软件标识：`M20-300-ISA-0.1-software`。

本文依据用户提供的[M20_300_architecture_v0_1.md](M20_300_architecture_v0_1.md)，记录本轮实际编码、汇编器与指令解释器。用户候选尚未明确的子编码、保留字段、标志更新和非法编码语义在此作**软件原型定义**，供后续评审；没有改写用户架构源文件，也不等同于已冻结RTL或已审计328颗MUX预算。旧8-bit取指/硬件LR的747方案不适用本ISA。

## 1. 地址、存储和编码总则

- ROM容量4096×16，PC为12位**指令字地址**。一条指令恰好一个16-bit word，不存在扩展字。`PC+1`是下一指令字，不是下一字节；正常下一PC按模4096回绕。
- RAM为256个4-bit单元，地址8位；A4、AR8、Z/C、GPO4为解释器架构状态。无B/T/IR/LR软件寄存器，不含硬件CALL/RET。
- `word[15:12]`为major opcode；`s=word[11:8]`为子操作，`aa=word[7:0]`为直接地址，`n=word[3:0]`为立即数。表中写0的保留位必须为0。
- 二进制镜像每word两个字节，**低字节在前**；例如`JMP 0x123`编码B123，文件字节为23 B1。`.memh`每行一个四位十六进制word，例如`B123`，行号0对应PC=000。
- 指令模型在执行期间保留当前PC，操作提交后才更新下一PC。无IR的ROM稳定约束须未来RTL/总线验证，本解释器不模拟引脚或传播延迟。

## 2. 完整编码表

### 立即数与AUX

|编码|指令|操作数与功能|标志|基础执行微周期|
|---|---|---|---|---:|
|000n|LDI n|A←n|Z←结果为0，C保持|2|
|100n|ADDI n|A←A+n，模16|Z/C|2|
|200n|ADCI n|A←A+n+C，模16|Z/C|2|
|300n|SUBI n|A←A−n，模16|Z/C（无借位）|2|
|400n|SBCI n|A←A−n−(1−C)，模16|Z/C（无借位）|2|
|500n|ANDI n|A←A AND n|Z更新，C保持|2|
|600n|XORI n|A←A XOR n|Z更新，C保持|2|
|7000|SHL|A逻辑左移1，补0|Z更新，C←旧A[3]|2|
|7100|SHR|A逻辑右移1，补0|Z更新，C←旧A[0]|2|
|7200|NOT|A←A XOR 15|Z更新，C保持|2|

立即数major 0..6的bits[11:4]必须全0；例如0010非法，不能静默截断为立即数0。AUX的low8必须为0，子操作3..F非法。

### RAM直接与间接（同一套子操作）

直接编码`8saa`；间接编码`9s00`，地址为AR。**间接指令的low8必须为0**，不提供隐含位移。下面所有RAM指令均计5个基础微周期。

|s|汇编|功能|Z|C|
|---|---|---|---|---|
|0|LD addr / LD [AR]|A←RAM地址处的nibble|更新|保持|
|1|ST addr / ST [AR]|RAM←A；A、AR不变|保持|保持|
|2|ADD addr / ADD [AR]|A←A+RAM|更新|加法进位|
|3|ADC addr / ADC [AR]|A←A+RAM+C|更新|加法进位|
|4|SUB addr / SUB [AR]|A←A−RAM|更新|无借位|
|5|SBC addr / SBC [AR]|A←A−RAM−(1−C)|更新|无借位|
|6|CMP addr / CMP [AR]|按A−RAM设置标志，A不变|更新|无借位|
|7|AND addr / AND [AR]|A←A AND RAM|更新|保持|
|8|XOR addr / XOR [AR]|A←A XOR RAM|更新|保持|
|9|OR addr / OR [AR]|A←A OR RAM|更新|保持|

子操作A..F非法。直接地址是0..255；每条读指令产生一次RAM读，ST只产生一次RAM写，不自动增加AR。第二操作数直接来自RAM，不借软件B寄存器，也不由宿主执行游戏算法。

### 地址、跳转、IO与系统

|编码|汇编|功能|标志|微周期|
|---|---|---|---|---:|
|A00n|ARL n|AR低4位←n|保持Z/C|2|
|A10n|ARH n|AR高4位←n|保持Z/C|2|
|A200|MOVARL A|AR低4位←A|保持Z/C|2|
|A300|MOVARH A|AR高4位←A|保持Z/C|2|
|A400|MOVA ARL|A←AR低4位|保持Z/C|2|
|A500|MOVA ARH|A←AR高4位|保持Z/C|2|
|A600|INCAR|AR←AR+1，模256|保持Z/C|2|
|Bxxx|JMP target|PC←12-bit绝对word地址|保持Z/C|2|
|Cxxx|JZ target|Z=1则取分支，否则PC+1|保持Z/C|2|
|Dxxx|JC target|C=1则取分支，否则PC+1|保持Z/C|2|
|E000|IN0|A←六键输入低4位|保持Z/C|2|
|E100|IN1|A←六键输入高2位，高位补0|保持Z/C|2|
|E200|OUT|GPO←A|保持Z/C|2|
|F000|NOP|仅PC+1|保持Z/C|2|
|F100|HALT|退役一次后进入HALTED，保持GPO|保持Z/C|2|

ARL/H的bits[7:4]必须为0；其它AR指令low8必须为0。AR子操作7..F、IO子操作3..F、SYS子操作2..F均保留，且IO/SYS所有有效子操作low8也必须为0。未提供DECAR、ORI、JNZ、CALL、RET；不能给保留码添加隐含行为。

## 3. 精确算术与标志语义

算术先计算未截断整数，再取低4位写回。ADD/ADC的C表示和≥16；SUB/SBC/CMP的C表示差≥0，即1=无借位。`SBC = A−R−(1−C)`，不是A−R−C。Z按4位结果是否为0设置；CMP只写Z/C。

LDI/LD/AND/ANDI/XOR/XORI/OR/NOT设置Z并保留原C。AR_CTRL及IO全部保留Z/C，**即使MOVA或IN改变A也不更新Z**。这与旧M20-747候选不同，是本轮对用户“PC/AR与IO不改Z/C”的明确化。程序若要判断IN/MOVA的值，应追加ANDI 15等明确更新Z的指令。

移位只有单步逻辑SHL/SHR，不存在自动多位移位或rotate-through-carry。数组索引、软件返回编号和游戏比较均应展开为现有指令。

## 4. 周期模型与计数口径

解释器按候选8状态执行流程计费：普通指令2微周期，RAM指令5微周期，taken/not-taken分支同为2。**2/5是本轮软件参考模型的约定，不是已执行的RTL周期仿真或FPGA/157实测时序。** 不包含额外WAIT、总线延迟、OLED刷新或真实按键同步/消抖时间；本轮没有实现这些功能。

|计数项|定义|
|---|---|
|retired|合法完成的指令数量，包含一次HALT，不包含TRAP/FAULT|
|cycles|从0开始累计执行微周期；非法TRAP/未映射FAULT各消耗2但不退役|
|reset_cycles|固定1，单独列出；每次reset开启新统计区间|
|total_cycles|reset_cycles+cycles|
|rom_reads|每次实际尝试取指一次，包括非法/未映射读取尝试|
|ram_reads / ram_writes|真实解释器RAM指令事务次数；直接/间接同口径|
|gpio_writes|OUT指令写次数，不是输出翻转次数|

无TRAP/FAULT的正常运行满足`cycles = 2×retired + 3×(ram_reads+ram_writes)`。若遇到异常，应另外计入异常取指的2周期；不能把它塞进已退役指令数。

给定CPU微周期频率f，`cycles/f`仅是上述模型下的执行时间预算；主机Python墙钟时间与CPU时间无关，50MHz板卡输入也不等于CPU微周期频率。Pong/Snake报告必须同时给模型条件，不将无OLED核心算法速率当完整游戏帧率。

## 5. 汇编器

入口：`m20.assemble(text, filename='<string>')`。返回`AssemblyResult`，含`words`、`symbols`、`listing`、`source_map`；另提供`binary`、`memh`和`used_words`属性。

```text
.equ CELL, 0x20
.org 0
start:
    LDI 8 // 2       ; //是整数除法，分号后才是注释
    ST CELL
    ARH 2
    ARL 0
    LD [AR]
    SUBI 4
    JZ done
    JMP start
done:
    HALT
```

- 指令助记符大小写不敏感，符号名大小写敏感；允许`label: instruction`。分号开始行内注释，`#`只作为整行注释；不把`//`识别为注释。
- 支持`.equ NAME, expression`、`.org expression`、`.word expression`。标签与常量不得重名；常量可依赖常量/标签，循环定义拒绝。`.org`必须在布局时能够求值，不能用未定的前向标签决定布局。
- 表达式仅允许整数、符号、括号、单目`+ - ~`、双目`+ - * // % << >> & | ^`。禁止函数调用、属性、导入和任意eval；移位量0..63，中间整数最多128位，AST复杂度受限。操作数不自动截断，越界报错。
- RAM操作可写`LD 0x20`或`LD [0x20]`，间接仅`LD [AR]`；其它RAM指令同样适用。SHL/SHR/NOT及MOVARL/MOVARH可显式写A或省略A。MOVA需写ARL或ARH，也接受规范内部名MOVA_ARL/MOVA_ARH。
- `.word`是明确的原始16-bit字逃生口，允许写非法编码以测试TRAP；普通助记符不会生成非零保留位。不能将`.word 0xFFFF`误当合法NOP。
- 未实现宏、include、CALL/RET伪指令或JNZ伪指令。软件返回ID由机器程序使用RAM存储和条件分派实现，解释器没有对应快捷操作。
- 每条指令和每个`.word`占1个word；`.org`重叠拒绝，地址范围0..4095。镜像覆盖0到最高发射地址，空洞填FFFF；**used_words是显式发射数，image_words是含空洞的地址跨度，ROM使用报告应同时列出**。
- 不自动把每个输出补齐4096word。ROM物理装载/未来RTL模型若需要全容量填充，应显式采用FFFF填充未加载空间，不能偷偷以NOP补齐后宣称程序执行正常。

## 6. CLI与输出文件

从工程根目录使用现有Python3.12环境（工具本身仅依赖标准库）：

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=host/python \
build/venvs/python312/bin/python -B -m m20 assemble \
  software/m20_300/pong.asm --output-dir build/m20_300/pong

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=host/python \
build/venvs/python312/bin/python -B -m m20 run \
  build/m20_300/pong/pong.bin --max-instructions 100000 \
  --trace build/m20_300/pong/trace.jsonl \
  --summary build/m20_300/pong/run_summary.json
```

游戏程序可使用持续tick循环，第二条命令在没有HALT时会以指令上限退出；不能把这种退出码2误判为CPU已HALT。正式场景基准另按明确的tick边界断点测量。

汇编输出：`.bin`、`.memh`、`.symbols.json`、`.source_map.json`、`.lst`、`.assembly.json`。统计含image_words、emitted_words、holes、image_bytes、capacity_words=4096、小端说明及二进制SHA256。

run支持`--entry`（word地址）、`--keys`（0..63）、`--format auto|binary|memh`。auto按.memh后缀选择文本，否则二进制；二进制必须是偶数字节，memh每个非空行严格4个十六进制字符，不接受地址标签/注释，最多4096word。文件读取SHA存为program_sha256，不能把memh文本哈希与对应bin哈希混为一谈。

CLI退出码：0=成功汇编或运行至HALT；1=源文件/参数/镜像格式错误；2=运行未正常HALT（如指令上限、TRAP、FAULT）。省略--trace时不积存完整轨迹，适合大规模游戏场景。

## 7. 机器接口、trace与异常

```python
from m20 import assemble, Machine
image = assemble(source_text)
cpu = Machine(image.words, ram=initial_ram, pc=0, keys=0, trace=False)
record = cpu.step()
summary = cpu.run(max_instructions=100000, stop_pc=word_breakpoint)
```

RAM夹具可为256-nibble列表或地址→值字典；未提供时使用全零**测试夹具**，不承诺真实SRAM上电清零。构造时检查word、RAM、PC和六键输入范围。正常CPU复位保留RAM；`reset(clear_ram=True)`是测试辅助操作，不能当成免费硬件清RAM功能。

复位状态A=0、AR=0、Z=1、C=0、GPO=8，PC默认为0，也可给测试入口；status=RUNNING，计数清零并单列reset_cycles=1。同步后的逻辑六键用keys掩码提供；IN只读掩码，不实现机械抖动、同步器模拟或软件消抖算法。

|trace字段|含义|
|---|---|
|sequence|当前已退役计数；异常不递增，不能当所有event唯一编号|
|pc / next_pc|取指地址/提交后地址，均word地址|
|word / opcode|完整16-bit原始指令，不只是高4位major|
|mnemonic|解码名称；未映射/非法取指可为null|
|a / ar / z / c / gpo|操作后架构状态|
|ram_transaction|null或READ/WRITE、address、value；WRITE附previous供调试，该previous不算真实RAM读事务|
|gpio / input|OUT写值/IN读值，其它指令为null|
|event / retired|RETIRE、TRAP或FAULT，以及本事件是否退役|
|cycles / cumulative_cycles|本事件执行成本/累计执行成本，均不包含单列reset1|
|status / reason|RUNNING、HALTED、TRAP、FAULT及异常说明|

HALT执行一次并更新PC至下一word，之后step返回None、不增加任何计数。非法/保留word使status=TRAP、PC保持原值、不改变架构寄存器/内存、不退役、增加2执行周期。

取指地址虽然在PC12范围内，但超出加载镜像长度时报告FAULT/UNMAPPED_ROM，消耗2周期且不退役，不默认为NOP。镜像内部.org空洞是FFFF，因此误执行会TRAP。宿主传入超范围数据属于配置ValueError，而不是已模拟出某种真实器件故障。

run遇stop_pc可返回BREAKPOINT且仍RUNNING；到达指令上限返回INSTRUCTION_LIMIT且仍RUNNING；HALT/TRAP/FAULT按状态停止。只有HALTED是正常结束，不把超时或断点当作执行成功。默认trace=True时保留逐事件字典；trace=False仍返回step事件但不在机器内累积列表。

## 8. 本轮边界

已能实际汇编、执行机器指令并输出统计/trace；没有RTL、总线波形、OLED像素、WAIT状态或157网表。具体游戏正确性场景、ROM使用及动态周期结果由本轮独立验证报告给出；本文件只规定工具和ISA语义，不自行宣布游戏或硬件阶段通过。
