# M20-300 V2：结构功能与精确资源审计结果

日期：2026-10-29（Asia/Shanghai）。**两版结构功能验证与资源审计通过；300/328颗数量目标未达到。** 尚未由用户确认正式阶段验收，本文件记录实际结果供决定后续优化或FPGA原型范围。

## 1. 八个问题的直接回答

|问题|当前有证据的回答|
|---|---|
|V2与V1是否等价？|在全部指定回归、单元穷举及逐周期锁步范围内等价，且与Python一致；未做全状态形式等价证明。|
|当前CPU需多少颗157？|本次共享网表**537个真实组合MUX实例＋33bit×2存储折算=603颗核心等价**，含30保持/33复位MUX；不是完整物理BOM。朴素版为738。|
|哪个模块最多？|共享版严格译码169个MUX最多；ALU107，PC含storage98、AR含storage95。控制/译码合计含state storage222。|
|原328是否合理？|作为本实现的成本承诺不成立：共享版超275。它只是早期点估，严格译码/控制、ALU与复位被明显低估。|
|能否压到300？|当前必须再减303，约占603的50.25%；没有证据保证可达，也未证明理论不可达。需要新的结构因式分解/架构评审，不能把未实现节省计入。|
|优化是否增状态或延长路径？|O1全局CSE减少135颗；状态仍33，2/5周期不变，MUX拓扑最大深度50→50。物理关键延迟/负载仍未STA或电气验证。|
|有不能直接转换成157的逻辑吗？|生成的组合网络只有MUX/常量/线，可逐实例转换；存储仍为nativeFF，真实2-MUX反馈DFF及辅助电路尚未物理实现。|
|FPGA仍可用原生FF吗？|可以，保留33个原生FF和组合网络；工具可能映射成LUT，但本审计不按LUT数计算157。|

## 2. 两版数量与优化效果

|指标|baseline|shared|变化|
|---|---:|---:|---:|
|实际组合MUX实例|672|537|-135（-20.09%组合）|
|其中CE/保持|30|30|0|
|其中复位选择|33|33|0|
|功能状态bit|33|33|0|
|DFF等价，2颗/bit|66|66|0|
|核心157等价合计|738|603|-135（-18.29%总数）|
|MUX拓扑最大层数|50|50|0|
|功能网络最大pin负载（含主输入）|34，rst|34，rst|0|
|MUX输出最大内部pin负载|21|21|0；局部分布可不同|

共享优化O1只合并完全相同`(S,I0,I1)`节点，包含重复NOT；没有增加状态、时分复用、FPGA运算器或新ISA。模块下降为decoder95、control13、ALU27，其余不变，合计135。61个唯一MUX有CSE复用记录，其中19个跨语义组，全部只按首个物理实例计一次；不能再加到537上。

baseline已采用同一前端的合理单热译码和四位加减复用，只是不启用全局CSE。未将这些初始选择伪装为额外优化收益，也没有刻意放大baseline。PC/AR共用增量器、写回选择重排、控制因式分解等只作后续研究，不填入虚构数字。

逐组/逐实例CSV、原328同口径偏差与共享规则见[精确预算](M20_300_V2_MUX_BUDGET.md)及[v2_resources/module_budget.csv](v2_resources/module_budget.csv)。比较时将各组reset移到集中复位行，避免重复计数：PC为86 vs82，AR87 vs62，ALU107 vs40，控制/译码加state storage219 vs76，集中复位33 vs12；所有行最终603 vs328。

## 5. 实例审计与资源边界

生成SV中每个MUX实例必须与连接JSON同S/I0/I1/Y。独立审计器不导入生成器，拒绝其它组合行为、隐含FF使能/复位、额外状态、组合环、未知信号、死网和纯debug门。共享归属按物理实例一次，跨组消费者只是同一输出连线。源哈希、pin表、FF-D和33位边界同时核对，不能靠修改一个JSON总数使审计通过。

603的storage66仍是约定折算：真实双MUX主从DFF尚未实现或测试；不能据此购买“603颗就能整板工作”。同步器storage至少另有24＋4，CE/reset/输入整形另审；RAM/ROM、时钟/复位/缓冲、总线方向/三态、供电PCB与调试分开。MUX输出21pin及rst34负载只是逻辑负载数，可能需要实际驱动/缓冲。

拓扑最长50层从ROM输入到功能端点，没有门延迟模型、STA、布线或可敏化路径证明；不能乘一个典型延迟便宣布Fmax。原语零延迟、nativeFF、ROM1.5ns/RAM2ns模型及10ns仿真时钟只验证数字契约，不代表157可以100MHz工作。

## 7. 决策边界

功能与精确计数的V2目标已完成；数量不是先前估计的328，也未实现300。即使假设169颗译码全部免费，现实现仍有434颗，因此不能期待只打磨一个小模块便达300；这只是当前网表的减法，不是所有微架构的下界。

若继续优化，应一次只改一个明确方案，记录面积/拓扑/负载变化并复跑本三方验证。下一步可研究译码/控制因式分解、结果/标志选择共享；PC/AR共用增量器和改状态可能有时序/选择/周期代价，须先评审。本轮停在可审计的603等价结构，等待用户决定，不提前进入FPGA板级或外设阶段。
