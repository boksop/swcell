# M20待决项与冻结清单

**等待用户评审，不开始RTL。** 已确定需求与以下推荐值必须区分。原有M11设计和结果不因M20方案改变。

## 1. 会阻塞RTL的架构决策

|ID|决策|推荐 / 备选|批准前的风险|
|---|---|---|---|
|D01|数据通路|先4位；8位作性能/成本备选|4位优先不是用户已冻结结论|
|D02|157数量目标|接受游戏配置627–747规划量级、工程预留至900；或重开300硬上限串行研究|不能拿漏计控制/CE的“300颗”承诺做PCB|
|D03|代码空间/编码|PC12、ROM4096字节、8位首字节、2字节跳转；每游戏独立镜像|真实程序未汇编；>3840字节需回评审，不能默扩到8KiB而不改ISA|
|D04|RAM/ROM接口|容量确定由FPGA或外部并口芯片提供，不使用157；AR8、256nibble及低4位不打包仍为提案|IS61WV5128BLL/MX29LV320E为用户候选；完整芯片容量不等于CPU自动能寻址|
|D05|调用|LR12单层CALL/RET，无硬件栈|需静态限制调用图，程序不能无意嵌套|
|D06|标志/边界|C为无借位、无N/V、取指/地址操作保留ZC|不一致会破坏所有多nibble算法|
|D07|控制与等待|6位≤64微状态、2位等待0..3；硬布线|控制门数尚未审计，扩状态/等待要改台账|
|D08|显示|CPU软件SPI、脏单元，无帧缓冲|实际控制器可能不满足规划的3命令/8字节单元假设|
|D09|输入/计时|六键同步、软件消抖/轮询/软件延时，无中断/硬件tick|CPU频率和程序分支会影响延时，需实测计数|
|D10|游戏验收规模|Pong至少持续操作；Snake16×8、最多64节、食物65候选有界|逻辑场地/得分绘制/单双人模式影响刷新预算|
|D11|CPU与AUX边界|FPGA只替存储/观察/装载，游戏完全在机器程序|将碰撞/像素生成交给FPGA将使验收无效|
|D12|额外器件|允许ROM/SRAM、三态驱动、时钟/复位/电源/键电气器件，单独BOM|157本身无可直接复用的运行时三态OE，不能硬接双向总线|

P0需对上述项目逐项“批准/修改/暂缓”，形成ISA版本。P1再以可展开网表闭合真实资源。本文没有替用户选择更改既有冻结结论，也未发现可确认的旧M20冻结结论。

|类别|需要的信息|可以暂不确定的范围|
|---|---|---|

|六键|连接方式、按下极性、上拉/下拉、是否共地/矩阵、是否已有电气去抖、功能分配|仿真用六路独立按键；若实际矩阵须重新计控制和扫描逻辑|
|ROM/NOR|用户举例MX29LV320ETTI-70G；需确定是否最终采用、BYTE模式、地址口径、时序/电平及预编程方式|已核对系列x8/x16能力；本轮不新增CPU自编程功能、不冻结物理连接|
|SRAM|用户举例IS61WV5128BLL-10TLI-TR；需确定最终选型、写时序、方向/电平和连接|系列为512K×8；本轮256nibble窗口仍是CPU提案，容量阵列不计157|
|157|实际厂商、完整型号/封装/温度等级、供电/负载、是否允许同类替代|SN前缀不据此认定为某厂数据表；不得混用不同器件典型时序|
|M20 PCB|时钟源/占空比/驱动/分配、复位来源、并行总线缓冲、观测点与实际负载|本轮仅逻辑端口；不分配引脚、不虚构PCB网络|
|FPGA连接|可用连接器/IO Bank/电压、允许占用的信号、屏和键实物接线|已确认的XC7K325T/50MHz只作为背景，不自动继承M11测点|
|预算/体验|是否接受约900颗工程余量、目标tick/显示效果、是否允许最小SPI外设|这些决定优先于开始RTL；不以假想高主频解决|

## 3. 已发现的重要工程差异

- 当前公共库是M11自动测试基础设施，没有通用结构级ALU/ITE库；未来要建立，不能宣称现成模块已验证。
- 现有Python解析器强绑定M11，日志快照接口也偏小；M20需要独立协议/适配并保留M11兼容，不能只改module字符串。
- snapshot_bridge是一轮冻结协议，不是持续逐指令流FIFO；扩用需要新握手。
- 新机Python3.12环境已准备不等于2026.1/器件/许可可用；本次不创建或调用新Vivado工程。
- M11高速成绩与M20时序/功耗/扇出无直接倍频关系；本轮软件目标频率只是预算输入。
- 旧首次Git纳管清单110文件未包含本目录规划文件及新增预算CSV，本次不改清单/忽略规则/索引；正式纳管前需按用户审查后的工作区刷新。
