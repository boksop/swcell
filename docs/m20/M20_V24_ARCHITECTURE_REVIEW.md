## 3. 十二个工程问题的明确回答

|问题|结论|
|---|---|
|1. 失败触发机制？|见上表；分别是延迟/分配/有效边界组合、guard不足、输入/控制违反及实际数据穿透，不能等同24个实体故障。|
|2. 最坏7ns损失来自哪里？|原模型聚合分配差−3ns＋有效锁存边界差−4ns；没有独立实测PCB、芯片、输出skew拆分，不能冒称PCB造成。|
|3. 20颗逻辑是否合理？|是：真值表/方向/钳位/无反馈成立；有可描述的条件工作区。其逻辑正确不产生最小死区保证。|
|4. TAP16何时D1/D2≥0？|平衡译码家族下τr、τf分别至少3＋L1、3＋L2 ns。原L=7ns时需累计各≥10ns（平均≥0.625ns/级）。|
|5. 何时≥4ns？|同家族各≥3＋L＋4；原L=7需各≥14ns（0.875ns/级）。必须另外满足脉宽、透明/建立和控制契约。|
|6. Buffer能否改善？|可以减少分配差/同相skew，但不同测试负载、温区和跨芯片条件不可混用；不能补足锁存边界或链min缺口。不作最佳型号排名。|
|7. 哪些真实路径有风险？|全部79组在不承诺min、源快/目的慢配对时有条件风险；假设0.25ns/级时52组负、27边界。局部实验观察到同样52条错误，未证明实体失效。|
|8. 频率作用？|升频压缩透明/建立和服务窗口；降频放宽这些预算，不改变完整脉冲域内同边沿D1/D2。超过脉冲适用域另判，不外推。|
|9. SAFE_HOLD需修结构？|未发现只能通过改变20颗逻辑才能规避的布尔竞争；任意时刻解除不安全，需FPGA相位/事务控制。当前没有全相位/实体签核证据。|
|10. 四tap足够吗？|已存在条件可行区，当前无证据要求加级数；也无证据保证16级在全物理角落足够。优先限定分配/有效边界与测链min/max，再讨论级数，不能只凭某个未定min失败增加BOM。|
|11. 必须实测什么？|每方向链/tap min/max、负载/探头/斜率、跨相与分支路径差、锁存有效开关及CQ/污染/hold、SAFE_HOLD传播和首周期、供电/温度/测量不确定度。|
|12. 正式进入C/D吗？|**暂不准入。** 保留20颗主线；先冻结一组可追溯的适用延迟/分配/控制预算，重新通过小型时序门禁，再评审C存储最小场景。|

上述10/14ns是此参数家族的条件关系，不适用于所有译码/钳位快慢组合。[更保守独立边界示例](ff16_resources/parameter_envelope.json)仍成立，要求可更高，不能用本轮简化家族覆盖它。

## 4. SAFE_HOLD与FPGA控制契约

20颗核心只钳位输出，不做自主RUN/STEP。建议FPGA额外服务状态（不增加实体157）至少区分 PARKED、RELEASE_QUALIFY、MASTER_SEEN、SLAVE_COMMITTED、DRAIN_WRITE、PARK_CONFIRM；最终状态编码不在本轮实现或冻结。

### FPGA自行产生参考

先断言SAFE_HOLD并使参考/链稳定。CPU_RESET仍有效，按完整Master/Slave序列初始化；不能仅“钳位即复位”。正常STOP等当前微周期和写事务完成，在Slave已更新稳定且仍透明的合格高窗口断言，确认全部叶端关闭后ack。

恢复若已保证Q=QM，可在C/Cd稳定高时释放SAFE_HOLD、等待所有释放路径完成，再产生完整下降/低/上升/高序列。重新开放旧Slave不能计作一次新提交；单步从新的完整Master采样开始，只承认对应Slave提交一次。需要明确是否包含D2收尾再park，不能以一次S边沿或参考电平改变代替完整微周期。

### 外部晶振持续运行

应将同一参考送FPGA，按实际同源/派生时钟约束或有预算的CDC识别合格高窗口。必须留足检测/调度/输出/PCB/两路钳位选择及叶端时序的上界；刚看到C=1并不意味着Cd、Slave/Q已稳定。若异步50MHz服务的检测和调度预算超过剩余高窗口，等待下一窗口，不能强行释放。不能假定2级同步或窄死区捕获零延迟。

安全高窗口释放的必要前提：Q=QM已知、H_RAW=1、S_RAW=1；解除时H即使有独立慢路径也应保持1，S只重新传旧QM。随后H释放必须及时完成，确保下一次完整Master窗口。可用充分的控制条件是“最慢释放完成早于下一C下降并留guard”；更精确分析可允许低窗口内完成，但必须验证其剩余计算时间和惯性过滤。

原晚释放的Master SELECT路径12ns，解除只比参考上升早1ns，导致整个Master窗口消失；本轮[10点必要窗口表](ff16_review_resources/safe_hold_release_budget.csv)是解析预算，未冒称新控制器仿真。旧正常park/resume仅手动延长参考窗口，不能升级为连续外部晶振任意请求相位通过。

### RAM事务与复位

STOP前要明确排空或保留pending事务；已持久写不回滚。恢复时WE可能一直有效，必须保留事务身份/完成标志，不把同一WE电平当第二次写。CPU_RESET取消未提交写、保留已写RAM内容；异常/紧急停车恢复应重新初始化。状态和确认用同步/握手，不把RUN请求组合门控到时钟。当前这些是**CONDITIONAL设计契约，完整实现/验证NOT_VERIFIED**。

Buffer树需保持启用并传递H=1/S=0，禁用后两相都低或高阻不是安全停车。参考突然停振没有独立时基时不承诺自动检测，另由FPGA/外部安全控制处置。

## 5. 后续准入门槛

1. **边界与来源：**分别取得或明确批准两方向τmin/τmax，原C路由、两译码/钳位路径、Buffer芯片/分支、PCB、有效开/关的独立边界；assumed不得标datasheet。
2. **A约束优先：**全部33×33在规定角落达到选定正guard，无缺窗、短窗、穿透。B路径分析只能补充，不能用少量未错替代。
3. **控制：**初始化、同源/外源释放、STOP/STEP、首完整周期和待写处理有单独可复现日志/断言。20颗逻辑不得偷偷由FPGA替代。
4. **C先最小场景：**明确新的快服务时基、PC/指令保持、RAM一次写、RESET边界和截止时间；`f_micro=f_REF`，不能沿用Johnson除8事件，也不能要求全BRAM访问挤入短死区。
5. C通过后再批准D完整87场景、57331事件等。本轮没有执行D，没有新commit/tag或远程操作。

本轮保留20颗架构，建议的下一项是上述预算/控制边界评审与所需实测，不是直接加延迟级或启动耗时CPU回归。
