# V2.4-B：根部到全部叶端的时钟预算

2026-11-04。**VERIFIED：既有记录复核与预算计算；CONDITIONAL：所有物理时序数值；真实PCB为NOT_VERIFIED。** 未修改20颗发生器、543 CPU或原A/B证据。

## 1. 定义、位置与7ns分解

ROOT取两颗SAFE_HOLD之后、外部分配树之前的MASTER_HOLD/SLAVE_OPEN，不是钳位前H_RAW/S_RAW。LEAF取锁存器真正有效开闭时刻，不是仅到封装选择引脚的时刻。

```
D1(i,j) = ROOT_S↑ − ROOT_H↑ + BS_r(j) − BM_r(i) + SO(j) − MC(i)
D2(i,j) = ROOT_H↓ − ROOT_S↓ + BM_f(i) − BS_f(j) + MO(i) − SC(j)
D1_LEAF = min(i,j) D1(i,j)
D2_LEAF = min(i,j) D2(i,j)
```

全部i、j均为0…32；最坏组合等于“最早打开减最晚关闭”，并已另导出全部113,256条配对（13个可分析场景×4tap×2方向×33²）。窄脉冲缺窗场景不能用完整脉冲公式，单独保留失败。

原快速链场景在每个叶端i人工设定：`Buffer=1+3i/32 ns`，有效开闭延迟`=1+4i/32 ns`。因此最早开放为叶0，最晚关闭为叶32；两方向均为：

|部分|打开端|关闭端|对裕量的贡献|
|---|---:|---:|---:|
|分配聚合参数|1ns|4ns|**−3ns**|
|有效锁存边界|1ns|5ns|**−4ns**|
|总损失|||**−7ns**|

这是**人为设定的独立快慢压力**。原聚合分配参数没有单独标定芯片、输出间偏斜或PCB；不能把−3ns全解释为走线，更不能把−7ns叫作实测PCB skew。原“六分支base＋叶残差”只是数值拆分，例如最坏闭端分支2的base=1.1875ns、残差2.8125ns；与开端分支0/base=1ns相减得到−0.1875−2.8125=−3ns，不构成器件级归因。

|tap|D1_ROOT / D2_ROOT|分配损失|边界损失|D1_LEAF / D2_LEAF|
|---:|---:|---:|---:|---:|
|4|0 / 0ns|−3ns|−4ns|−7 / −7ns|
|8|1 / 1ns|−3ns|−4ns|−6 / −6ns|
|12|3 / 3ns|−3ns|−4ns|−4 / −4ns|
|16|5 / 5ns|−3ns|−4ns|−2 / −2ns|

这里TAP16上升相对参考：根H↑=5ns、根S↑=10ns，Master32最终关闭=14ns、Slave0打开=12ns。下降方向根S↓=5ns、根H↓=10ns，Slave32关闭=14ns、Master0打开=12ns。根部先后正确仍不足以保证全部叶端先后。

[根/叶分解104行](ff16_review_resources/root_leaf_decomposition.csv)、[TAP16全部33位事件264行](ff16_review_resources/tap16_leaf_events.csv)包含参考/事件绝对仿真时间、相对时间、branch、传播参数和有效边界。所有场景的6,864条叶事件在原始新运行中保留。

晚释放场景首周期缺失的有效事件保留null，其完整周期D1/D2只对应后续可配对周期，不能用正的周期裕量证明首次启动。113,256配对是完整脉冲配置解析值；异常瞬态仍以原trace和缺窗计数为准。

**位置限制：**原小型平台的33个测试位没有CPU物理寄存器布局映射。CSV中的CPU网表顺序名称为明确标注的示例索引，不是板上位置；真实短路径实验每次另选实际源/目的寄存器。任何装配/布局承诺都不能据此产生。

## 2. 新模型将哪些项分开

新扫描在每叶分别记录 `chip_common_assumed_ns`、`output_branch_assumed_ns`、`pcb_assumed_ns`、有效开启/关闭项；上/下降路径仍独立。完整参数例见[explicit_leaf_parameters.json原始目录](../../build/m20_300/v24_ff16/deep_review_r4/explicit_leaf_parameters.json)。这些是灵敏度坐标，不能当成原7ns已经被物理辨识。

跨相不匹配、同相分支spread和PCB差只能在来源独立/不重叠时相加。如果已经用整条路径的min/max求差，不要再无条件加一遍已包含的同芯片output skew。输入端原始C到OR/AND的走线不匹配也要单列，不能只预算延迟链。

### 静态电平和默认安全

全部候选可讨论低频/静态电平；CDCLVC文档明确DC输入，仍需满足输入斜率和最小脉宽。**Buffer禁用不等于SAFE_HOLD：**LVC244禁用为高阻，AVC两款禁用弱拉低，CDCLVC低使能输出低；这些状态都不能同时给出H=1/S=0。尤其H被拉低会开放Master。正常停车应保持分配树工作，由上游SAFE_HOLD提供两种不同安全电平。上电、FPGA未配置、任一电源掉电时的默认行为必须单独落实。

### 负载与分支数量

每相33选择输入按6/6/6/5/5/5分支示例分配。NC7SZ157原表CIN典型2pF的测量条件为VCC=0V；据此粗估每支5～6输入的芯片部分约10～12pF，并非3.3V下的实测/保证负载。加上走线/焊盘/探头后不能保证仍在AVC的15pF测试点内。CIN没有保证最大值，不能据此签核驱动能力。根部还需驱动分配Buffer输入电容，延迟链选tap4/8/12还直接驱动一个后级I0；选tap16少这一输入，但不是零寄生。

NC7SZ157单输出至少每相6个分支Buffer；244可用一封装每相6通道；AVC每相至少两封装；CDCLVC1106可一封装每相六支。这只是单层覆盖数量的逻辑示例，不是完整树/BOM，所有Buffer均不计入20颗发生器。

## 4. 不混淆保证范围的条件比较

以不同封装的独立传播范围求保守差，另假设PCB最坏差1ns、有效锁存边界差4ns，要求guard4ns。在本轮平衡译码家族中根间隔为累计链延迟−3ns：

|Buffer|独立传播跨度|所需ROOT间隔|所需TAP16累计最小链延迟|
|---|---:|---:|---:|
|NC7SZ157|未知，缺保证min|不能据原厂值求出|不能据原厂值求出|
|244，−40～125°C|6ns|15ns|18ns|
|AVC1004/1022|4.5ns|13.5ns|16.5ns|
|CDCLVC1106|1.2ns|10.2ns|13.2ns|

这只是“原厂指定点＋假设系统差”的CONDITIONAL比较；不包含实际分支超负载、供电/输入走线差，也未用其同芯片skew替代跨相误差。若使用CDCLVC的0.5ns等条件两芯片匹配，需要另证明等条件成立；即使成立，也不能去掉未知的锁存边界差。**Buffer可以减少分配误差，不能补上延迟链保证min或自构锁存器规格。**

## 5. 可交给原理图/布局与实测的约束草案

- 每相树保持相同层数、受控负载及已记录的芯片/输出归属；源到树输入、树输出到叶端分别预算，不只等长最后一段。
- 上/下降分开记录每叶端的Buffer延迟、输出skew、PCB传播、选择端斜率及有效透明边界；同时保留最早开/最晚关的不同位组合。
- 装配只接一个参考源、一组两相来源、一个tap；禁止短接推挽输出。上游SAFE_HOLD必须具有默认安全态，Buffer不以禁用代替两相钳位。
- 测量CLK_REF、所有tap/Cd、根H/S、各分支及代表最坏叶端；注明探头电容、阈值、负载、电源、温度、参考脉宽和抖动。
- 验收计算必须含有效锁存边界和测量不确定度；先给每方向链min/max及分配/边界预算，再选择tap和频率。4ns仅工程假设，不能冒充原厂hold参数。

这份约束可指导后续预算和测试，**当前不构成PCB时序放行或原理图定版**。
