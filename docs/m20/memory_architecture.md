# M20存储器架构

## 用户明确的两种实现方式（2026-10-28补充）

**RAM/ROM不由157搭建。两种方案的存储容量阵列均计0颗157；只对SwCell CPU需要的接口电路计数。** 这一点是已确定需求，不再列为待决的存储实现原则。

|方案|提供存储容量的一方|157 CPU仍负责|预算边界|
|---|---|---|---|
|1：FPGA提供RAM/ROM|FPGA内部存储资源及其适配端|PC/AR地址生成、IR/数据接收、读写控制及约定等待|FPGA存储阵列/适配端不计157；CPU寄存器和CPU侧接口仍计|
|2：外部并口芯片|SRAM与并行NOR，例如下列候选|同样的地址、数据选择、CE/OE/WE/方向及等待|外部存储芯片不计157；驱动/电平/复位等独立BOM不隐藏|

方案1既适用于FPGA功能原型的存储后端，也可作为真实157 CPU的外部存储提供方；后者需单独核实FPGA与CPU的接口电平、采样相位和读写延迟。FPGA不能因为提供存储器就顺带代替CPU执行译码、地址运算或游戏逻辑。

|用户举例器件|厂家资料对应组织|对当前提案的影响|
|---|---|---|
|IS61WV5128BLL-10TLI-TR|IS61WV5128BLL系列512K×8异步SRAM|与8位物理RAM接口匹配；4位CPU可先只使用低4位，不需要用157构造存储单元|
|MX29LV320ETTI-70G|MX29LV320E系列32Mbit，可4M×8或2M×16|可评估x8 BYTE模式直接读8位指令，避免仅按x16读时的额外字节lane选择|

容量/总线组织依据[ISSI官方系列数据表](https://www.issi.com/WW/pdf/61-64WV5128Axx-Bxx.pdf)和[Macronix官方MX29LV320E数据表](https://www.macronix.com/Lists/Datasheet/Attachments/8542/MX29LV320E%20T-B%2C%203V%2C%2032Mb%2C%20v1.3.pdf)。用户以“比如”给出候选，不等于最终封装、模式、电平或连接已经冻结；不根据10/70速度后缀直接推CPU频率。

并行NOR在本提案运行期作为只读程序ROM，擦写/烧录由独立编程流程完成；**当前747不含CPU在线Flash擦写/编程控制器**。如未来需要CPU自己写Flash，应另行定义命令、忙状态和写保护并重新计数。

两颗芯片物理容量远大于本提案的PC12/AR8可见空间。暂时仅映射一个小窗口，其余高地址按最终接口方案处理；若要使用全部容量，需增加CPU地址位/寄存器、编码或分银行机制，不能在保持747预算的同时默认获得完整寻址能力。

CPU侧直接控制与等待在当前预算内为12+16=28颗；PC/AR/IR已经分别计数，不再重复放入“存储接口”项。方案1若改成不同逻辑接口、方案2若使用打包或新控制功能，28及全CPU总数必须重新审计。详细单点预算见[mux_budget.md](mux_budget.md)。

## 1. 推荐逻辑契约

Harvard结构：PC12直接寻址4096个**程序字节**；AR8寻址256个**4位数据单元**。程序不能直接写ROM，数据空间不映射代码。首版每个游戏使用独立ROM镜像，不先实现启动菜单/双游戏共存。代码必须能在4096字节内表达；建议P3以≤3840字节为门槛，保留至少256字节余量。

|接口|逻辑宽度与方向（以CPU为主体）|语义|
|---|---|---|
|ROM地址|输出12|程序字节地址|
|ROM数据|输入8|opcode或扩展字节，取样前稳定|
|ROM读控制|输出有效/读相位|只在明确取指窗口活动|
|RAM地址|输出8|nibble单元地址，读写期间不变|
|RAM读数据|输入4|物理8位接口低4位|
|RAM写数据|输出4|A值；物理高4位固定0，不保留旧值|
|RAM控制|输出读/写/驱动使能|读与写互斥；写脉冲是一次事务，不是每个等待拍重复写|

这些是逻辑名称/方向，不是PCB网络、封装脚号或XDC。CPU不依赖标准AXI、SPI存储器或免费外部READY。

## 2. 等待与物理访问

采用静态配置`W_R/W_D/W_W∈0..3`和CPU内2位WCOUNT；来源为常数/板级配置，暂不做运行时编程寄存器。计数、重载、译码计入16颗157预算。若未来器件要求更多等待，必须扩宽并修订预算/CPI，不能让FPGA自动多等却不计硬件。

|周期|读|写|
|---|---|---|
|SETUP|地址稳定、OE/CE有效，加载WCOUNT|地址/A数据稳定，写缓冲开启，WE保持无效|
|SAMPLE/PULSE|等待W个附加拍后采样数据，且只写寄存器一次|WE保持有效1+W拍，地址数据不变|
|RELEASE|停止读、保持地址，随后才允许改变PC/AR|WE无效完成一次写，保留规定hold后关驱动/改地址|

基础每事务3拍，附加等待为W。地址/OE建立到读采样的规划预算为`(1+W)T`减去CPU输出/走线/输入建立预算，必须覆盖器件tACC/tOE；不能直接把3T全算成读取裕量。写脉冲约`(1+W)T`，还要分别检查setup/hold/turnaround。初始W=0只是仿真基线，不是对未知外部器件的时序保证。

无READY引脚的异步NOR/SRAM由固定等待访问。FPGA BRAM适配器必须在同一CPU可见相位返回数据；超出预算则报验证失败，不悄悄拉长周期。故障模型可以延迟到预算内外测试边界，但不能凭空替CPU提供未计费握手/缓存。

## 3. A/B/C候选比较

下面是相对推荐**不打包**接口的边际结构代价，不包含已计入CPU的PC/AR/IR、共同控制或外部存储容量；不能再加一次整套寄存器预算。

|方案|映射|附加MUX/状态估算|结论|
|---|---|---|---|
|A：4位+8位物理存储|ROM每地址一个8位指令；RAM每地址低4位一个nibble|不需lane选择/RMW；控制和写缓冲使能已入主预算|推荐，RAM容量利用50%，接口简单|
|A打包RAM|一字节含两个nibble|读选4MUX；写需8位缓冲约24颗、按lane合并约8颗、控制约6..16：约42..52颗额外|节约外部容量不等于节约157，首版不选|
|B：4位+16位不打包|ROM每个16位**字**低8位存一指令；RAM每字低4位存一单元|可直接连低位，未用数据位常数/忽略；不需要假设硬件BYTE模式|功能可用，但ROM/RAM利用50%/25%，更多物理引脚|
|B打包ROM|16位字放两个指令，PC低位选lane|8位2:1选择=8MUX；若再加预取缓存，16位带使能约48颗，加有效/控制|只做组合lane选择较可控；缓存不免费|
|B打包RAM|16位字放4个nibble|读4路选择12MUX；16位缓冲约48颗；合并约16颗；控制约8..20：约84..96颗额外|无nibble写选通时必须读改写；首版不选|
|C：8位CPU+8位存储|程序字节、RAM字节直接用|CPU状态/ALU扩大，见资源文档；RAM单字节可存一个身体位置|性能可能更好，不是本次推荐的面积最小候选|
|C+16位存储|低8位不打包或两个字节lane|组合读选8MUX；如没有合适写选通，字节写同样可能需要RMW|取决于真实器件，不能假设所有x16 SRAM/NOR有相同BYTE接口|

预算不把厂商BYTE#/LB#/UB#能力当成通用事实。ROM若按“每字低8位一个opcode”布局，PC递增1是到下一个物理字，外部地址转换必须统一；不能一处按字、一处按字节生成镜像。

## 4. 总线方向、外部器件与BOM边界

157输出没有可供正常访问使用的三态OE；不能将CPU常驱动MUX输出与SRAM读数据直接对接。建议一组至少4位可控三态写驱动，RAM读时释放；若用8位总线器件，未用高位按确定规则处理。驱动器/电平转换器是额外BOM，类型/数量TBD；它不计成157，却必须单列，不能称为“全CPU仅157”。ROM可独立读总线，避免ROM/RAM地址/数据仲裁额外MUX。

物理存储地址引脚可能多于12/8，高位应按容量/片选/编程方式定义固定值，待器件确认。CPU直接从已编程异步并行ROM/NOR取指；不在执行路径后台用SPI Flash或FPGA处理器替它取译码。NOR擦写属于外部编程流程，不是本ISA的一部分。

FPGA原型RAM可以BRAM实现，但CPU可见只有256个4位单元；不能让软件偷偷访问额外BRAM保存帧缓冲、栈或大数组。参考模型与硬件适配器的读延迟均遵守上述契约。

## 5. Snake数据空间提案

|地址（nibble地址）|容量|用途|
|---|---:|---|
|00..3F|64nibble|变量/参数/软件指针/临时值|
|40..BF|128nibble|64个身体位置，每位置连续x、y各1nibble|
|C0..DF|32nibble|16×8单元占用位图，128bit|
|E0..FF|32nibble|额外临时/测试签名/保留|

总共256nibble=128字节有效信息，占用256个物理8位单元。身体表和占用位图是CPU维护的数据，没有FPGA碰撞硬件。详见game_feasibility。完整128节蛇需要256nibble身体再加变量/位图，本方案不支持；本提案最大长度64，必须用户冻结后才实现。
