# SwCell M20-300：4-bit 游戏 CPU 微架构与 FPGA 仿真计划

**状态：架构候选 v0.1，未冻结；未实现 RTL、汇编器或 FPGA 工程。**

## 1. 设计目标与不可跨越边界

- Pong 首先可玩；Snake 验证动态间接 RAM、数组、循环与分支。游戏状态和决策均由 CPU 程序完成。
- CPU 核心目标约 300 个单路 2:1 MUX（即 157 等价数量）；计数须按结构级网表验证，当前仅预算。
- FPGA 版 CPU 状态元件使用原生 FF，其组合逻辑要有明确的 ITE/MUX 结构映射；不能从 LUT 数量倒推 157 数。
- 物理 RAM/ROM 由外部芯片或 FPGA 存储后端提供，不计入 157；但 CPU 侧地址、数据、控制与状态必须计入。OLED、按键的接口逻辑及板级辅助资源另列完整 BOM。
- Vivado 2026.1、XC7K325T；引脚和 PCB 外设连线待定；此阶段不生成工程、不编写 RTL。

## 2. 与旧 M20-747 的主要区别

| 特性 | 原先参考方案 | M20-300 提案 |
|---|---|---|
| 数据宽度 | 4bit | 4bit |
| 程序取指 | 8bit/字节，有 IR 与扩展字 | 16bit/指令字，不设 IR |
| PC | 12bit，借 ALU 分段自增 | 12bit，独立组合增量器 |
| RAM | 8bit 地址；4bit 单元 | 8bit 地址；4bit 单元 |
| 操作数 | A、B、T | A；RAM/立即数直接作第二操作数 |
| 返回地址 | 12bit LR | 无硬件 LR；软件返回编号 |
| 微状态 | 63 | 8 |
| 目标门数 | 627–747（估算） | 约 328 核心预算点估，待计数 |

## 3. ISA 和程序存储器

- ROM 为 `4096 x 16`，PC12 按**指令字**寻址（不是原方案的字节地址）。物理 x16 异步 NOR 可使用 word mode；FPGA 后端保留完全一致的 CPU 可见语义。
- PC 在当前指令直到退役之前保持不变，组合 `ROM[PC]` 不经 IR 寄存器。`FETCH_WAIT` 负责保证 ROM 输出稳定。
- 指令字高4位为 major opcode；低12位为随指令解释的操作数。非法或保留字段非零应进入 TRAP（具体合法编码表须定稿）。

### 主 opcode

| 高 nibble | 指令族 | 编码解释 |
|---|---|---|
| 0 | LDI | 低4位立即数；A←n |
| 1 | ADDI | A←A+n，更新 Z/C |
| 2 | ADCI | A←A+n+C，更新 Z/C |
| 3 | SUBI | A←A−n，C=无借位 |
| 4 | SBCI | A←A−n−(1−C) |
| 5 | ANDI | A←A AND n |
| 6 | XORI | A←A XOR n |
| 7 | AUX | [11:8] 子操作：SHL、SHR、NOT等 |
| 8 | RAM_DIRECT | [11:8] 子操作，[7:0] 直接 RAM 地址 |
| 9 | RAM_INDIRECT | [11:8] 子操作，地址来自 AR |
| A | AR_CTRL | [11:8] 子操作，低 nibble 可作立即数 |
| B | JMP | 12bit 绝对指令字地址 |
| C | JZ | Z=1 跳转至12bit绝对地址 |
| D | JC | C=1 跳转至12bit绝对地址 |
| E | IO | [11:8] 子操作，读取按键银行/写 GPIO |
| F | SYS | NOP/HALT 等，非法编码 TRAP |

RAM_DIRECT/RAM_INDIRECT 共享子操作：0 LD、1 ST、2 ADD、3 ADC、4 SUB、5 SBC、6 CMP、7 AND、8 XOR、9 OR。除 ST 外，ALU 的第二输入直接取稳定 RAM 数据，不增加 B 寄存器；CMP 只更新 Z/C。

AR_CTRL：0 ARL n、1 ARH n、2 MOVARL A、3 MOVARH A、4 MOVA ARL、5 MOVA ARH、6 INCAR；DECAR 暂不冻结。

IO：IN0/IN1 输入六键两银行；OUT 将 A 的4位写入 GPO（MOSI/SCLK/DC/CSn）。OLED 的复位由独立板级复位信号提供，首版不占 CPU GPO。软件消抖属于程序逻辑；异步按键必须经过单列的同步/输入整形资源，不能把 FPGA 免费 FF 隐藏在 CPU 预算中。

Z 表示最后一次相关结果是否为 0；C 为加法进位，减法无借位；load/logic 按冻结后的精确规则更新 Z 或保留 C，PC/AR 与 IO 控制不改变 Z/C。

**不含硬件 CALL/RET。** 软件程序可把 4bit return_id 存在 RAM 中，然后 JMP 至共享例程；例程结尾读取返回编号并显式条件分派。只承诺单层返回；ROM 容量/动态周期必须经真实汇编验证。

## 4. 微架构寄存器

PC12、AR8、A4、Z/C2、GPO4、uSTATE3，共33个状态位。每位真双MUX DFF 计2个157，核心状态基础为66颗；所有 CE/保持、同步初始化、组合译码和写源选择必须另计。板级六键两级同步为12bit、24颗额外157当量（若由其他物理器件实现须列入BOM），复位同步2bit需4颗额外157当量。

## 5. 8状态执行控制

- `RESET=0`：清 PC/AR/A/flags、设置安全 GPIO；禁止 WE。
- `FETCH_WAIT=1`：PC不变，等待外部 ROM 一次稳定周期。
- `EXEC=2`：计算 ALU、写输出、跳转、PC+1；或转入 RAM 事务。
- `MEM_SETUP=3`：RAM 地址与数据建立，写无效。
- `MEM_ACCESS=4`：读采样/运算写回，或产生单次 RAM WE 脉冲。
- `MEM_RELEASE=5`：结束 RAM 事务、更新 PC，随后 FETCH_WAIT。
- `HALT=6`：停止 retire，保持输出安全。
- `TRAP=7`：非法指令状态，禁止 RAM 写。

普通指令约2微周期；RAM 指令约5微周期。精确的边沿、输入稳定和 BRAM 仿真读延迟由 RTL 时序表与断言落实。ROM 输出只在 PC 稳定时解释；PC 在整个 RAM 事务保持。若加入存储器 WAIT，必须另审计状态/计数器开销。

## 6. CPU 核心初步 MUX 预算（目标点估，不是证明）

| 模块 | 状态 MUX | 其它 MUX（含使能） | 小计 |
|---|---:|---:|---:|
| PC12 + 递增 + 绝对跳转 + 保持 | 24 | 58 | 82 |
| AR8 + 递增 + 写源选择 + 保持 | 16 | 46 | 62 |
| A4 + 写源选择 + 保持 | 8 | 12 | 20 |
| Z/C2 + 保持 | 4 | 2 | 6 |
| GPO4 + 保持 | 8 | 4 | 12 |
| uSTATE3 | 6 | 0 | 6 |
| 4bit ALU + 立即数/RAM选择 | 0 | 40 | 40 |
| RAM地址（AR/指令直接地址） | 0 | 8 | 8 |
| 按键银行/极性输入选择 | 0 | 10 | 10 |
| 初始化/复位/安全覆盖 | 0 | 12 | 12 |
| 控制器译码及下一状态 | 0 | 70 | 70 |
| **合计（CPU核心目标点估）** | **66** | **262** | **328** |

- 328 属于“300颗左右”的初步设计规模，**不是物理网表或上界**。尤其控制器70、ALU40、复位12是待实现估算；结构审计后可能明显变化。
- 如果六键两级同步、复位两级同步也必须由157实现，至少另外计24+4=28颗，因此该口径约356颗，还未计时钟缓冲、SRAM三态驱动、PCB支持器件。**不得宣称完整PCB只有328颗芯片。**
- 对真实CPU必须分别统计：2-MUX-DFF storage、CE/保持、MUX组合逻辑、物理非157辅助芯片、FPGA原型辅助资源。
- 验收阈值建议：完成无隐藏行为门的精确结构清单后，CPU核心应争取≤330；如果>360则回到架构评审；如要求严格≤300，必须明确哪些功能削减或是否接受外部控制器件，不能修改数字凑预算。

## 7. 存储器契约

- ROM 逻辑端口 `rom_addr[11:0]`, `rom_data[15:0]`，PC 稳定期间组合/异步读取，必须满足 tACC/tOE；FPGA BRAM 可在 FETCH_WAIT 适配一次同步读延迟。
- RAM 逻辑端口 `ram_addr[7:0]`, `ram_dout[3:0]`, `ram_din[3:0]`, `ram_we`, `ram_oe`, `ram_ce`，每个地址一个 nibble，不做打包读改写。
- 物理 x8 SRAM 的上4位数据输出不能直接固定接地，读时会驱动；数据通路需要受控的方向/三态支持器件，必须另列BOM。
- 访问等待与实际存储器时序须验证；任何适配器不得修改 CPU 退役语义或偷偷实现游戏操作。
- 游戏各自编译独立 ROM 镜像，不承诺同时常驻；Snake RAM 可以继续使用旧规划的00..3F变量、40..BF身体环形表、C0..DF位图、E0..FF scratch，但软件返回编号必须占用指定 scratch 单元并防止重叠。

## 8. FPGA 原型和模拟仿真规划（尚未执行）

### V0 — 先做独立 ISA 软件参考模型

Python 编写指令编码/解码、汇编器、4096×16 ROM 镜像生成器、256×4 RAM 和逐指令解释器。参考模型不得复用 RTL ALU/FSM；支持完整 retire trace (`PC, opcode, A, AR, Z, C, ram_transaction, gpio`)。建立 Pong/Snake 核心算法的真实机器程序（先无 OLED），以 ROM 字数与动态指令验证软件返回、动态身体表、碰撞、食物和位图算法。

### V1 — CPU 功能 RTL 和 XSIM

仅实现 `m20_cpu_core` 和 `m20_bus`, `rom_model`, `ram_model`；CPU 真正的状态元件采用 FPGA 原生 FF，核心组合逻辑逐步用 MUX/ITE 封装。建立独立 testbench，对照 Python 模型的 retire trace；测试所有合法/非法指令，穷举 4-bit 算术，覆盖 RAM直接/间接、PC跨FFF、AR跨FF、复位、HALT/TRAP。允许在 XSIM 中加入可配置 ROM/RAM 延迟。

### V2 — 指令级及随机回归

随机程序、错误注入、不同存储器延迟模型；断言 ROM 在访存期间稳定、无错误写脉冲、写读互斥、RAM 访问地址不变、退休时状态一致。所有参考数据都从独立模型导出。

### V3 — Pong 集成仿真

CPU 实际跑机器指令、更新 RAM、读取带反弹模型的按键、CPU 生成 SPI 电平；由 testbench 只负责**被动**解码 SPI 命令和重建像素帧，不可替 CPU 计算球/碰撞。统计程序大小、帧刷新周期、读写次数、程序轨迹；Pong目标≥10Hz，优选≥15Hz（指定 CPU 时钟/屏幕条件）。

### V4 — Snake 集成仿真

16×8逻辑场地，最大64节（或由软件测试后冻结）；覆盖边界、自撞、进入旧尾格、增长、食物冲突与生成、长度上限、游戏重新初始化；OLED SPI 仍由 CPU 驱动。建议目标≥5Hz，所有时序/ROM占用以实际 trace 衡量。

### V5 — 157 结构资源审计

将 CPU 组合逻辑限制为唯一的 ITE 原语与可证明共享的子电路；从层级网表累加实例，2-MUX DFF 位逐一计2、CE另计；与 V1 行为模型逐指令等价。超预算先做共享优化，不许用 Vivado LUT 数量冒充 157 数。

### V6 — Vivado 2026.1 FPGA 原型

在板级外设管脚确定后再创建独立工程。默认 XC7K325T、板级50MHz输入；使用 MMCM/BUFG 或 clock-enable 产生可调 CPU 频率（如100kHz、1MHz、2MHz、5MHz，实际时钟以时序报告为准），BRAM仿真 ROM/RAM，GPIO连接OLED和六键，ILA/串口导出 retire/errors/CPU状态；保留独立测试 ROM。不得引用 M11 原版工程作为 M20 工程的构建产物。

### 验收关口

1. ISA 真正可编程且 Pong/Snake 机器程序内存与执行周期成立。
2. 全部算术/跳转/访存单测通过且参考模型/RTL retire trace 全匹配。
3. MUX 数经过结构级可审计，物理 DFF 和使能开销均已计入。
4. FPGA上板后的游戏状态与仿真一致；板上时序通过；外设引脚由实际硬件表给出。
5. CPU 本体满足约300颗目标的经审计成本或明确批准的偏离值。

## 9. 需要在 RTL 之前确认的风险

1. 无IR要求 ROM 在整条 RAM 指令期间保持稳定，不能引入PC提前递增。PC/RAM时序需严格断言。
2. 16位程序 word 地址不能与旧8位 byte 地址混用；跳转和编译器/汇编器统一按 word 编址。
3. 无LR、软件返回ID可能导致 ROM 超4096 words 或动态返回分派成本过高；必须先用实际游戏微程序验证。
4. 328仅为预算点估，特别是控制器和ALU未逐门实现；如果超标需要重设计，不能宣称目标已实现。
5. 157构成双MUX DFF的物理时序、复位、扇出、功耗不能由FPGA FDRE验证替代。
6. OLED控制器/屏幕像素、SPI命令、六键IO极性、板级时钟与接口引脚均待用户提供，测试模型不得假定最终PCB网络。
