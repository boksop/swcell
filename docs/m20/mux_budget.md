# M20资源预算：157颗数与可审计结构

**这是规划估算，不是综合/网表计数。** 数量的单位是“单路2:1 MUX等价157颗”，不使用FPGA LUT/FF报告倒推真实封装数。若实际采购多路器件，封装BOM另算，不能暗改基本口径。

## 本轮口径澄清：存储器阵列均为0颗157

用户明确两种存储器实现：①FPGA提供RAM/ROM；②外部并口器件提供RAM/ROM，例如IS61WV5128BLL-10TLI-TR与MX29LV320ETTI-70G。两者的**RAM/ROM容量阵列都不使用157，计数均为0**。本文件原627–747预算已经采用这个边界，不包含用157搭建256-nibble RAM或4KiB ROM的成本，因此这里不从747扣除存储阵列。

保留在157 CPU中的PC/AR/IR/A/B/T/LR是执行与接口寄存器，不是RAM/ROM阵列；存储器换成FPGA或专用芯片后它们仍然需要。FPGA仅提供存储器时，不额外承接CPU译码、寄存器或游戏算法。若整个CPU也在FPGA上原型，下面只是**目标157实物CPU的等价数量**，不是原型板需要焊接747颗芯片。

## 1. 计算规则

`ITE(s,b,a)=s?b:a`计1。NOT=1；AND/OR各1；XOR可用一个共享反相加一个ITE计2。带使能DFF为2颗存储MUX+1颗反馈选择=3颗/位；不能只计2。多路写源、清零/常数选择、译码单独计，不假设FPGA CE/reset免费。

k选1的w位普通树按`(k−1)w`估算，未证明的常数折叠/共享不提前扣减。所有“控制器范围”仍待P1展开，不是可靠上限。外部RAM/ROM容量不计，但其CPU地址/选通/读写接口和等待计数全部计入。

`*` uSTATE的hold、复位强制零、解码与下一状态没有免费省略，集中在最后一行；不能再把下一状态预算算到每个模块，也不能只留下12颗状态存储。其它每位hold已在寄存器表计入。组合写源/PC读选择/等待计数各有唯一归属。

ALU54拆分：4位加/减链28（每位通用全加器5，加上条件反相2，共7×4）；AND4；五路结果选择16；zero归约4；carry/shift/0标志选择2。XOR使用加法器已有propagate；SHR主要为连线，仍占结果选择的一路。可优化不等于已经优化。

译码120的可复核构造：每个4位输入全解码用共享4个反相，每条minterm 3个AND，共`4+16×3=52`；opcode/field两组104，再用16个AND限定B子操作。硬件真值表共享可能减少它，也可能增加其它控制；必须在P1审计。

完整配置表中固定取值小计507，加控制120–240=627–747；最小配置少LR36和相应读源12，固定取值小计459，加控制96–192=555–651。这里“固定取值”只表示表内选择的数字，不表示所有模块已逐门实现。8位粗模型为寄存器256、操作数67、ALU106、写回24、键/存储/端口/译码/等待共170，固定取值623，加控制120–280。8位ISA尚未冻结，不能把这个模型当实际计数。

工程预算向上取整并保留小量整档余地，所以不把`747×1.2=896.4`伪写成“已证明≤900”。**900是希望闭合的规划预算，不是已验证上界。** 本阶段没有可审计网表，控制项甚至可能超出该范围；P1输出才可认证数量。若实际高于批准预算，回到P0，禁止改表凑数。

## 4. 与300颗的冲突

仅本提案完整配置的寄存器220+操作数选择51+ALU54+写回12，已经337颗，尚未计等待、译码、控制、键银行等。因而这条**明确结构方案**无法满足300；这不是证明所有可能的MUX CPU都不可能300。

|可选优化|规划可省/新增|代价与限制|
|---|---|---|
|不做CALL/LR|约省48及部分控制|SPI代码重复/4KiB程序压力；可最小CPU先行，不能先承诺游戏软件完整|
|PC降12→8|PC存储约省12、读选择约省4；LR也缩短再省类似量|仅256字节程序，游戏大概率不够；必须改跳转编码和代码证据，不能当等价优化|
|RAM地址降8→4|地址状态约省12和一组读选择|16nibble不够Snake环形表/位图，拒绝用于完整配置|
|按键同步移出CPU|表面省24|只是转移到外部BOM/FPGA；若实物仍需要，不能从系统总成本消失|
|ROM/RAM打包|可能增加约8或42–96颗|节省存储容量，不必然减少CPU面积|
|1位串行ALU/移位寄存器|值得为300硬上限另行研究；本次不写虚假节省数|地址/数据串行、周期与软件全面重算，不是换一个ALU参数即可|
|精简/共享译码|120可能减少，但须按等价网表证明|不能靠删掉下一状态、enable或reset预算实现纸面达标|
|外部微码ROM|可能减少大量控制MUX|多一套控制存储器/BOM，项目“主要157”边界须用户决定|

## 5. 外部BOM与未计入项

ROM/SRAM存储芯片、至少一组受控三态写驱动、OLED及按键/电阻、时钟源与分配缓冲、电源/去耦/复位器件不换算成157，但必须进系统BOM。82个DFF对应约164个时钟选择端负载；不能假设单个时钟输出可直接驱动且保持M11时序。缓冲数量/布线/电平转换TBD，不能据本表估PCB面积/功耗/成本。

FPGA UART/轨迹BRAM/主机链路/测试超时/程序装载器不计入目标CPU，必须在网表层级和利用率中单列。不得把CPU的真实控制/寄存器挪入这些辅助层。

## 6. 未来独立资源审计

1. P1建立唯一ITE/寄存器结构原语，冻结NOT/XOR共享及CE/reset展开规则；黑盒primitive只能是已声明的状态绑定或外部器件。
2. 不依赖Vivado LUT报告：从专用结构清单/中间网表按层级累计ITE实例、状态位、enable/reset/写源；共享节点只算一次。
3. 分别记录未经优化的可追溯构造数量、等价验证后的共享数量、实物封装BOM。禁止减掉在FPGA被CARRY/DSP/LUTRAM吸收的CPU逻辑。
4. 对组合库穷举/形式等价，对共享控制和寄存器映射进行状态/退役等价；为每项优化留下前后数量与证明。
5. 拒绝CPU核心中的隐式`+`、`case`、variable shift、数组索引等未展开结构；参考模型和FPGA辅助可用行为运算，但不得混入核心计数。
