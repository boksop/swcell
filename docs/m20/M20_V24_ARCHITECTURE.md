# M20 V2.4 架构评审与实施契约

2026-11-03，设计阶段。V2.3模式A已独立冻结为aecf570c2e33563179e95e1615fd005cc19817f5，tag m20-v2.3-two-phase-sim-verified。V2.4不修改CPU ISA/477组合/33状态，不将新增问题反标V23失败。本文先于新RTL落盘，测试状态另见报告。

## 1. 同源参考与服务接口

模式B（FPGA单路）与C（外部晶振等效）经静态互斥0Ω选择同一CLK_REF，**同时送Johnson及FPGA时钟输入**；不默认异步CDC。模式A保留FPGA直接两相作为参考。源/两相必须成对静态选择，不做运行中热切换。

发生器状态在CLK_REF上升后更新；FPGA在下降边沿采样稳定的4位相位码及CPU总线。此为相关时钟半周期路径，需要显式约束参考占空比、源/返回PCB延迟、相位状态最大传播和FPGA输入setup；不能逐位异步同步后假定原子。RUN/STEP请求若来自其他域，则在纯157发生器中使用两级状态同步。单步使用toggle/ack，仅一项未确认请求。

接口输入：公共CLK_REF、相位状态4位、发生器busy/fault、CPU原ROM/RAM总线。FPGA不复制Johnson递推作为隐藏计数基准，也不译码CPU指令。服务只解释公开相位协议：

|源状态|服务下降沿|动作|
|---|---|---|
|0000（首M）|t=0.5T|锁存RAM地址/CE/OE/WE/data；启动同步读或形成pending写|
|0111（D1）|t=3.5T|pending RAM写单次持久化|
|1111（首S）|t=4.5T|CPU Q已稳定，锁存ROM地址/启动同步读|
|其余|无新请求|只推进同步读流水，输出保持|

读响应为请求后两个服务边沿。RAM在2.5T返回，M关闭约3T，留约0.5T扣IO/PCB/组合逻辑/setup/guard；ROM在6.5T返回，下一M约8T，留约1.5T扣返回与建立。初始研究T=1000ns（fREF=1MHz、f微周期=125kHz），非板外实测，不假定8MHz一定满足。

**写服务版本变化明确记录：V23在内部M-close CE写；V24在D1下降沿写。** 两者都在CPU实际Slave提交前。CPU仍2/5微周期，写一次及先写后读不变；复位取消/不回滚专项以真实存储提交事件对齐，不能沿用旧内部CE冒充同一物理时刻。如果原精确接口契约需要M-close同刻写，则该部署不可直接替换，应保留V23模式A。

Prime服务仅停钟/初始化使用；故障时禁止新请求并取消未提交写。ROM/RAM由可综合FPGA侧服务实现，模拟IO/PCB延迟单独包装。后续实际FPGA使用专用时钟资源/时钟引脚及generated-clock、input/output delay约束；本轮不创建板级工程或STA。

## 2. Johnson本机互锁：仍是待验证候选

本地H=CLK_REF OR S，本地S=CLK_REF AND H，用两颗MUX形成反馈。上升要求H先关闭Master再经反馈允许S；下降先关S再经反馈允许H打开。所有本机状态（含同步控制）使用相同本地两相反馈MUX DFF，不用FPGA FF代替。

该结构有异步反馈；不能由布尔式直接宣告可信。须分别检查稳定时的唯一解、未知启动、最小数据/选择延迟、所有状态位分支偏斜、短脉冲、控制复位与可复现重叠负测。实际死区仅约一条反馈传播弧，并非完整参考周期；若最小弧小于最坏本地分支/选择偏斜，明确失效并禁止该配置。没有实测最小延迟，不作NC7SZ157 hold签核。零延迟和有界数字延迟测试必须分开。

## 3. 控制、异常与资源边界

13位发生器状态：Johnson4、RUN同步2、STEP-toggle同步2、已接受token1、完成ack1、active1、step_mode1、sticky_fault1。属于发生器，不加入543核心；2MUX/位=26存储MUX，反相/复位/保持/译码/同步选择/互锁全部实际计数，不以17为目标。

正常仅在1000安全边界启动、继续或停车；停钟保持1000，CPU H=1/S=0。单步执行完整八参考周期，完成后ack并停在1000；RUN优先，连续运行时STEP可保持待处理，RUN停止后执行。请求方在ack前不再次toggle。所有保持通过D反馈选择，不门控参考时钟。

非法状态或inactive但不在1000将置sticky_fault，先冻结相位状态并关闭输出；**下一参考边沿才修复到1000**，避免多bit修复同时越过译码而未先保护。故障不自动继续CPU执行；必须复位/初始化CPU和接口后重启。非法注入本身可能产生错误相位，不承诺无损恢复，单元测试记录故障检测和安全状态。

上电rst异步钳位输出，内部同步复位需参考边沿；参考未起振时只保证输出钳位，不保证13位已经初始化。正常STOP依赖参考继续；任意停振不自动检测，允许外部rst紧急钳位，重新起振后完整初始化。不能把紧急中断当正常事务完成。

## 4. 实施/验收顺序

1. 生成并独立审计显式MUX网络、状态映射/资源；本机互锁单元检查优先，不先跑CPU长回归。
2. 正常/非法16状态、reset/RUN/STEP/STOP/停振/负测；若新理论缺陷无法闭合，暂停并报告。
3. 同源服务单元与窗口预算，负测验证错误窗口，不以异步2FF替代相关时序分析。
4. 模式A/B/C使用同一543核心和原87/57331输入，保留完整状态/微周期/事务/RAM/Python对照；复位专项按实际服务提交点对齐。
5. 原始证据在独立build/m20_300/v24目录；交付报告供审阅，不创建V24验收tag，不做PCB/新选型/M0-M19/远程。

## 实施后审查检查点：暂停

当前116颗候选在已配置参数下完成A/B/C各零/延迟87/57331与全部异常回归。但发现本机双MUX模型两级SELECT_NS共用，未覆盖独立器件混合快慢；H/S输出因果顺序不能保证有效锁存时序顺序。详见[M20_V24_DESIGN_REVIEW.md](M20_V24_DESIGN_REVIEW.md)第6节3.2ns理论重叠反例。尚未运行该新混合弧测试；按用户“先提出并中断”要求暂停，不能把本架构当无条件正确，不标V24验收通过。
